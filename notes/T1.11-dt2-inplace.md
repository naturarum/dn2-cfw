# T1.11: Digitakt II 1.17 and section 4's in-place loader

Date: 2026-10-05. Status: **done**. Marks: **[verified]** = checked against the bytes or run
here; **[inferred]** = reasoned from structure. Private: nothing here goes to anyone until the
user decides (ROADMAP C8).

Everything ran offline: Unicorn through digikit's harness, on the code of Elektron's stock
Digitakt II 1.17 file. No device was touched and nothing was flashed.

## Answer

- **The Digitakt II has the same second loader.** Digitakt II 1.17's section 4 is
  byte-identical to Digitone II 1.12's, except one byte: the ELE3 product-word compare at
  `0x80003d30` (`moveq #0x2b` on DT2, `#0x34` on DN2). Its main-OS loader `0x8000357c`
  stages section 3 at **`0x40200000`** and depacks in place to `0x40000400` with its copy of
  the depacker, `0x80005728`. **[verified]**
- **On the Digitakt II it is Elektron's own file that fails.** The 1.17 image is 3,275,616
  bytes, so a stream staged at `0x40200000` stays ahead of the writer only if it is at least
  1,179,488 bytes long. Elektron's stream is 1,147,584 bytes: in-place margin **−31,912**.
  Run under Unicorn, the unit's own section 4 loader, given the stock file, writes over the
  stream's last unread bytes. From `0x403187c5` on, the image comes out wrong, and it never
  reaches the main OS. That holds with either DDR state tried (the harness's 0xA5 fill, and
  the pattern section 4's own DDR test leaves). **[verified]**
- **elekloader's Digitakt II builds pass that loader.** elekloader's packer is looser than
  Elektron's on this image (1,385,586 to 1,386,032 bytes), so its builds have a margin of
  **+205,910 to +206,092** at `0x40200000`. The unit's section 4 loader gives exactly the
  intended image and enters the main OS at `0x400004e8`. That was checked on a no-mod
  rebuild, on core-dt2 alone, and on core-dt2 with each of the two DT2 example mods.
  **[verified]**
- **Control:** the bootstrap's normal boot path (loader `0x80000596`, stage `0x40400000`)
  gives the intended image on all five files, stock included. **[verified]**
- **elekloader's check does not cover this path.** `syx.verify` measures the in-place gap at
  the profile's `stage`, `0x40400000`, only. A synthetic mod with 240 KB of zeros in `.run`
  passes elekloader's verify (gap 2,057,581) but has margin −39,571 at `0x40200000`, and the
  unit's section 4 loader corrupts it. **[verified]** No shipped mod is like that; it shows
  the check's gap, not a live problem.
- **When the bootstrap takes that path:** the same as on DN2. Boot flag bit 6 (`0x80008404`)
  is set only at `0x80000b9a`, and only when the power-on key read `0x80001276` returns −1:
  one of its seven replies did not arrive within 10,001 polls. The bootstrap code for this
  (entry, flag builder, key read, UART8 send and poll, the boot path, the routine that runs
  section 4) is byte-identical to DN2 1.12's. **[verified]** That this read is the front
  panel's is **[inferred]**, as on DN2.
- **So:** a Digitakt II on 1.17 whose panel does not answer the bootstrap's key read in time
  hangs in the section 4 loader with Elektron's own file, and would boot with elekloader's
  current builds. **[verified]** in emulation for the loader. That a real unit behaves the
  same is **[inferred]**.
- **Correction to T1.2:** T1.2 had the two Digitakt II stream sizes swapped. 1,147,584 is
  Elektron's stream, and 1,385,586 is elekloader's (the no-mod rebuild here gives exactly
  1,385,586). Its rough estimate of −31,904 was therefore for the stock file. The measured
  minimum is −31,912. **[verified]**
