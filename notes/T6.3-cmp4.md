## 1. What CMP4 is

CMP3 (on the unit since 2026-10-21) with three changes:

1. **The delay slot is Elektron's again.** Recipe `CMP4` (`tools/dspsplice/build.py`) does not patch the two delay
   CJUMPs (`0x1c1c58` process, `0x1c166c` init: key `stock_hooks`, a build check that both keep the stock bytes in the
   final image), and builds and loads no tape delay: code2 (`0x310000-0x318000`) keeps the stock contents (key
   `code2_unused`: the final-image diff may not touch it). The stock delay runs its own code (L2 `0xb8482c`, init
   `0xb848cb`) with its own state, the DDR slot at `0x8005912c` that FTD1's tape delay borrowed [verified, build.json
   `stock_hooks`, `image_diff_ranges`].
2. **SC01's breathing meters** (`tools/dspsplice/src/cmp_glue.c` `cmp_mtr`: per band, every block, q = round(1310 x
   clamp(gain reduction dB, 0, 25)) of the band's y2, no hold, no state; CMP3's CmpMeter FILL gone). The glue is
   SC01's text, on CMP3's layout (code4 at `0x2e2900`).
3. **comp-link-dn2 0.3** in the main OS (SC01's: the CMP3 storage review's two fixes, notes/SC01-review.md), and
   **flanger-names-dn2 0.1** in place of fx-rename-dn2 0.1: fx-rename's 13 flanger sites with the same strings and none
   of its 16 tape sites, so every delay name is stock (`scripts/cmp4_make_mod.py` writes its mod.json, checking each
   stock value and that the sites are fx-rename 0.1's flanger sites but the symbols' prefix; a new example in the fork,
   `examples/flanger-names-dn2/`, so fx-rename 0.1 stays as FTN1..CMP3 build it).

their calls aimed at where CMP3's `td_process` (`0x18ad4a`) and `td_init` (`0x18ac0a`) were (stub step `cabs`, a call to
an absolute SW address; tools/dspsplice/stub.py), where CMP4 loads nothing. Nothing reaches them: the delay CJUMPs are
stock, and no code of ours names them (only stubs.s defines them) [verified]. Rebuilt this way, block 1 is byte for
byte CMP3's (17,974 B) [verified].

## 5b. Limits

- Unit only: the real DSP load (the estimate is CMP3's minus about 16k instructions), the sound, a power cycle with
  saved band values, Overbridge (it refused our builds' version field before; not addressed here).
- comp-link 0.3 closes the kit-switch race only partly (notes/SC01-review.md: the window `0x40031e78..0x40031f90`).
- The two delay stubs in block 1 are dead bytes; a later build that frees block 1 can drop them (the flanger then moves).
- Kits saved on SC01: X 1..6 (MODE 2..7) and k 40 values up to 127 stay in the kit until X is turned; Overbridge would
  see them.
