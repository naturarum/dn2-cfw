## 1. Layout study

### 1.1 The problem

| | bytes | where it ran before |
|---|---:|---|
| the tape echo (spaceecho.c + se_glue.c, selcc -O1) | 39,390 | SE01 `0x308400-0x311dde` (never on the unit) |
| the compressor (mbcomp.c + its two stubs) | 31,110 | CMP3 code3 `0x308400-0x30fd86` |
| demand on L1 block 2 | **70,500** | |
| block 2 where code of ours ran on the unit, without the tape delay | **56,204** | `0x308400-0x315f8c` (CP2F code3 to `0x30ff76`, FTD1's tape `0x310000-0x315f8c`) |

The 14.3 KB gap cannot go into `0x315f8c-0x318000` (the `forbid` rule). The other code-proven ranges are full:
block 1 `0x2dd600-0x2e1c36` (the flanger, which must stay identical) and `0x2e2900-0x2e4f46` (CMP3's glue and
cmp_tail.c, 9.8 KB). All code-proven ranges together give 84.0 KB for 98.3 KB of code.

### 1.2 What must be in L1 (sharcvm profile, `tools/dspsplice/sc01_profile.py`, `out/SC01/SC01-dsp/profile.json`) [verified]

Every function of SE01's and CMP3's images, instructions per block, steady (knobs still) and moving (every knob each
block), and at the effect init:

- **per sample** (the hot loops): `se_run` (12,656 B, 34-56k instructions per block), `mb_run` (11,222 B, 34-39k),
  `mb_state_expo` (1,610 B), `mb_out_bands` (3,158 B, 7.1k while a MIX moves);
- **every block**: `se_control` (9,810 B, 2.8-5.8k), `spaceecho_process`, `se_crackle_plan`, `se_process` (the glue),
  `mb_control`, `mb_implausible`, `mbcomp_process`, `fxh_comp`, `mb_targets` (about every 6th block), the helpers they
  call (the compressor's own copies of the fxmath helpers, `fx_sin2pi`, `fx_rand(s)`, `fx_absf`);
- **only while a knob moves**: the tape echo's `se_mix_targets`, `se_pan_gains`, `se_filter_coefs`, `se_targets`,
  `spaceecho_set`, `spaceecho_time_samples`, `spaceecho_fb`, `se_heads`, `se_res` and its own copies of the fxmath
  helpers; the compressor's `mbcomp_set`;
- **rarely**: `se_crackle_event` (a crackle tick), `spaceecho_set_bpm` (a tempo change), `mb_restart` (a guard trip);
- **boot (and a re-init)**: `spaceecho_init` (17.6 M instructions once: the 4 MB tape), `se_init`, `fx_onepole_a`,
  `spaceecho_snap`, `mbcomp_init`, `mb_clear`, `mbcomp_snap`;
- **never on the DSP**: `spaceecho_heads`, `_center_hz`, `_bw_oct`, `_q`, `_trim`, `mbcomp_ratio`, `mbcomp_gr_db`
  (1,062 B; the Mac API and tests use them).

### 1.3 Level 2: stock code that is dead in this build (`tools/dspsplice/sc01_deadcode.py`, `out/SC01/SC01-dsp/deadcode.json`) [verified]

The brief's figure for the stock compressor (~16.6 KB) is its instruction count per block, not its size: the routine
is **2,342 B**. All the stock FX code our hooks bypass, in L2 (executed through the I-cache, as all stock L2 code is):

| range (SW) | L2 bytes | B | what | callers |
|---|---|---:|---|---|
| A `0xb83eaf-0xb84926` | `0x20007d5e-0x2000924c` | 5,358 | the stock delay: process `0xb8482c`, init `0xb848cb`, all their helpers | only the CJUMPs at `0x1c1c58`, `0x1c166c` (hooked) |
| B `0xb84943-0xb84c1f` | `0x20009286-0x2000983e` | 1,464 | the stock chorus's modulated delay and output (`0xb84943`-`0xb84b39`) | only from C |
| C `0xb84ccb-0xb84dee` | `0x20009996-0x20009bdc` | 582 | the chorus's biquad driver `0xb84ccb` and its entry `0xb84d5c` | only the CJUMP at `0x1c1be1` (hooked) |
| D `0xb84fd3-0xb85466` | `0x20009fa6-0x2000a8cc` | 2,342 | the stock compressor: entry `0xb8541d`, driver `0xb85396`, the five stages | only the CJUMP at `0x1c215c` (hooked) |

The proof, per range: (1) every call, jump, conditional jump, fall-through and indirect edge of digikit's sharcdb
(8,611 edges) that lands in it comes from a hooked CJUMP or from another of the four; (2) the instruction before each
start is a return (`jump (m14,i12) (db); ...; rframe`); (3) no literal, data reference, pointer base or absolute access
names an address in it, in SW, L2-byte or word form, but its own pushed return addresses; (4) no 32-bit word anywhere
in the stock final image (every loaded block: L1, L2, DDR) equals an entry address in any of those forms; (5) no root
(interrupt vector, task, code-pointer table) lies in it. Nothing in the image takes the L2 code block as data (the
three `0x20000000` literals are IMASK bit constants and the init program). **The paths that stay live, checked:** the
chorus init `0xb84f51` (our stub tail-jumps there) calls `0xb84926`, `0xb84c1f` and `0xb84f20`→`0xb84dee`, all outside
B and C; the compressor init `0xb85501`→`0xb85466`→`0xb84faa` and the meter getter `0xb8552b` (called at `0x1c3108`,
calls `0x1c0c76`) are outside D. **At run time:** with sharcvm's profile on, CMP3's image (where A-D still hold the
stock code) executes no instruction in them over its effect init and 800 blocks with every effect on and the knobs
moving [verified, `profile.json`]. Further stock code only the dead FX code calls (`0xb80bfc`, `0xb80c6e`, two chorus
biquads in L1 block 3) is under 0.6 KB in scattered pieces: not used.

### 1.4 The layout chosen [verified: `out/SC01/SC01-dsp/build.json` layout_check and functions]

| range | level | what |
|---|---|---|
| `0x2dd600-0x2e1c36` | 1 | stubs, flanger, flg_glue: CMP3's bytes but the two delay-stub targets |
| `0x2e1c40-0x2e23a8`, `0x2e2400-0x2e24d0` | 1 | CmpSlot, CmpTail (FILL), as CMP3; CMP3's CmpMeter is gone |
| `0x2e2900-0x2e4de4` | 1 | the compressor glue and cmp_tail.c (9,444 B; CMP3's ran to `0x2e4f46`) |
| `0x2e4de4-0x2e5df4` | 1 to `0x2e4f46`, **3** above | boot-time init: `spaceecho_init`, `mbcomp_snap`, `mb_clear`, `mbcomp_init` (4,112 B; 3,758 B above `0x2e4f46`) |
| `0x2e6000-0x2e6044`, `0x2e6800-0x2e686c` | 1 | constant data, stub save area |
| `0x300000-0x308400` | 1 | FlgSlot (FILL) |
| `0x308400-0x315e3e` | 1 | everything per sample and every block of the echo and the compressor, the knob code that fits (`se_targets`, `spaceecho_set`, `spaceecho_time_samples`, `spaceecho_fb`, `se_heads`, `se_res`), both comp stubs: 55,870 B, 334 B left before `0x315f8c` |
| L2 A `0xb83eb0-0xb84926` | **2** | the echo's knob code (`se_mix_targets`, `se_pan_gains`, `se_filter_coefs`, `spaceecho_set_bpm`) and its own fxmath helpers: 5,094 of 5,356 B |
| L2 B `0xb84944-0xb84c1f` | **2** | `se_crackle_event`, `mb_restart`: 1,448 of 1,462 B |
| L2 C `0xb84ccc-0xb84dee` | **2** | `se_init`, `fx_onepole_a`: 502 of 580 B |
| L2 D `0xb84fd4-0xb85466` | **2** | `spaceecho_snap`, `mbcomp_set`: 2,330 of 2,340 B |
| SeSlot `0x8005912c-0x80451814` (DDR) | 1 | the stock delay's state, which FTD1's tape delay used on the unit |
| left out | | the seven functions the DSP never calls (1,062 B) |
| `0x315f8c-0x318000` | | nothing (key `forbid`; the final-image diff too) |

Why: the hot loops and every-block code in L1 (single cycle, no cache, where our code runs on the unit now); the
knob-change and rare code in level-2 memory (stock code ran exactly there, through the same I-cache path; nothing
calls it in this build); level 3 only for the boot-time init, the smallest set that closes the gap, so a fault there
shows at the first power-on and not mid-session. **The level-3 reason:** `0x2e49c4-0x2e6000` is CP2F's watermark page
23, which CP2F's scanner read on the unit about every 0.27 s and found intact ("the memory scanner empty"), it lies
directly above code of ours that runs on the unit (CMP3's code4 to `0x2e4f46`), 8 KB below the DM cache at its
largest (`0x2e8000`), in a different block from the range that failed. It is still a range where only data of ours
has run, which is also what `0x315f8c-0x318000` was before CMP2 put code there [inferred: the cause there is unknown].
Without it the layout misses by 3.1 KB (1.4 KB with the fxmath helpers shared between the two effects).

Alternatives looked at and not taken: moving FlgSlot (33.8 KB) to free `0x300000-0x308400` (no proven DDR room: the
stock delay's DDR has 31.6 KB spare after SeSlot; the flanger's code and timing would change); free L2
(`0x2008823c-`; dnfw found run-time pointers in `0x200918c0-0x200c2000`, so "statically free" is weak there); other
unreferenced stock L2 functions (5.6 KB at `0xb8d001` is a driver with a jump table: deadness not provable as for the
FX code); one copy of the fxmath helpers for both effects (1.7 KB, a link-level change to the proven compressor code:
not needed once level 3 is used).

How it is built (`tools/dspsplice/build.py` recipe SC01, keys `split`, `place`, `l1`, `level3`, `code4_proven`, `l2`):
each function of selcc's output goes to the section of its region (`split_asm`; local labels stay inside a function,
calls are absolute CJUMPs, verified in the listing), with a marker label so build.json lists where each function went;
the four L2 sections are linked at their SW addresses (seld takes START = 2 x SW) and patched into the stock L2 payload
block in place (no new block), each over the stock bytes it replaces (their sha256 in build.json). Build checks: every
`l1` function in block 2; in code4 only the `level3` functions after the glue; every block inside its slot and out of
FORBIDDEN and `forbid`; the final image differs from stock only at the six hooks and in the planned ranges.

## 2. Changes beyond the merge

- **FDBK on the stock law** (`fx/spaceecho.c` `spaceecho_fb`): loop gain per head = FDBK/64 (64 = 100 %, endless;
  127 = 198 %), a leaf, exact (x 1/64); SE01: 1.1 x^1.5 (x = FDBK/127). Bounded: the tape saturator clamps its input to
  +-1.5 (tape at +-1) and the wet ceiling holds the output at 0.7. `fx/` tests 331/331 (`make test`; the INT law test
  now checks v/64 exactly; the AGE noise test runs at INT 17.5, SE01's 27 %: at 78 % per head the echo's own build-up
  counted as noise; the fuzz, 120 s with INT 127 half the time and bursts of +-4: peak 0.7000, no bad sample or state).
  A/B renders (`fx/renders.sh` group `se_fdbk`, `out/T3.11/ab.html`; `out/SC01/logs/fdbk_renders.txt`): one head at
  FDBK 32 dies (-63 dB 1 s after the input), at 64 holds (+1.1 dB), at 100/127 holds at the ceiling; SE01's law at
  the same knobs next to each (`fxrender_se01`, built from the frozen `src/se01/`), and the stock delay (emulated).
  The other TAPE renders keep their sound: their INT values converted to the same gain per head (64 -> 25.2 ...).
- **Meters** (`src/cmp_glue.c` `cmp_mtr`): every block q = round(1310 x clamp(gain reduction dB, 0, 25)) of each band's
  y2, no hold, no fall of its own, no state (CMP3's CmpMeter and its FILL gone); half-word 11 as before. CMP3's glue is
  frozen in `src/cmp3/`.
- **comp-link-dn2 0.3** (`store.c` `compl_update`): `live` read before the stock slot-17 call, our words written only if
  `self+0x20 == stored` and `getter(self) == live` (listing `out/SC01/main/compl_update.lst`: getter, `0x4002ffca`, the
  `+0x20` compare, getter, compare, encode); the id-0 word put back unless a k in 0..24 is named (single: k > 24; vector:
  none <= 24, unsigned). CMP3's 0.2 builds from the fork's 4b1384b (`scripts/elk_pin.py REV_CMP3`).
- **fx-echo-dn2 0.2**: `fxe_tick` also clears bit 2 of row 0x7a's display flags (0xc -> 0x8, as every delay row). Bit 2
  is read only by the knob draws (through `0x400372fe`: `ParameterPageView::vslot45` keeps the label when it is set);
  the lock gate `0x40064ccc` reads bits 0 and 3 [verified, decomp]. SE01 builds fx-echo 0.1 from 59cd41f.

## 4. Load

Instructions per block in sharcvm, load = (1.30 x instr + 11k) / 666,667 [inferred calibration]: typical (the mix,
one head, FDBK 50, bands at MIX 39) 371k mean / 374k max = **74 %**; busy (three heads, FDBK 64, AGE 64, bands at MIX
64) 385k / 388k = 77 %; RND runaway 397k / 404k = 79-80 %; **worst** (noise, every band knob and MIX moving, every echo
and flanger knob jumping, key) 415k / 420k = **82.5 % / 83.6 %**; brick checker 376k. CMP3 at the same compressor
settings with the delay slot silent: 370-378k vs SC01's 373-380k. For CMP2 the estimate said ~74 % where the unit
measured ~50-60 %; scaled the same way SC01 would be about 55-60 % typical and 60-68 % worst [inferred]. Not counted:
the echo's tape reads in DDR (three heads, 24 floats per sample) and I-cache misses of the L2 code (it runs only while
knobs move or a RND head jumps: 1-3.5k instructions per block then, about 0.2-1.5 % if every line missed [inferred]).

## 5. Limits and open points

- **Level 3**: 3,758 B of boot-time init above `0x2e4f46`, where no code of ours has run (1.4). A fault there would
  show at power-on [inferred]. The other risks of the layout: L2 code through the I-cache is new for our code (stock
  code ran from exactly those addresses); deadness rests on digikit's decode being complete (statically) and on the
  CMP3 profile run (dynamically).
- **FDBK**: existing kits on the tape delay's law (1.1 x FDBK/127: 64 was 55 %) now repeat for ever at 64 and grow
  above; two heads run away from about 32, three from about 21. The ceiling holds it 2.5 dB over the stock runaway.
- **Meters**: no hold, so a quick band at REL 0 flickers; the UI samples the half-words at about 30 Hz.
- CMP3's and SE01's limits hold (notes/T6.3-cmp3.md 4, notes/T5.3 7). The review's optional +0x96 clear after the
  old-format converter is not done. Unit-only: real DSP load, the sound, a power cycle with saved band values.
