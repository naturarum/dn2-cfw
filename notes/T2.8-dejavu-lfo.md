## 1. Research: where the Digitone II computes its LFOs [verified, read instruction by instruction]

**On the ColdFire, not the DSP.** Two evaluators in the main OS; the DSP only ever sees the modulated parameter.

- **Evaluator A, `FUN_40137a06`** (audio tracks): called once per SPI frame by the frame handler `FUN_40025e36`
  (vector 191) at `0x400272d4`, **1,500 times a second** (one 32-sample block at 48 kHz). It loops over the **16 voice
  rows** (not tracks: a row is a voice, owned by a track, `0x80005308 + 4r`), 3 LFOs each, LFO3 first. Inputs: the
  smoothed parameter rows `0x800068e4 + 0x22 + 0xca r + 2k` (the frame handler's one-pole smoother runs first, so LFOs
  act after smoothing), the tempo rate `0x402a132c` (120 x BPM), the trig mask. State: 40 bytes per LFO at
  `0x44640c18 + 0x78 r + 0x28 l`: +0 phase (a cycle is 1,382,400,000), +4 output, +8 RAND's value, +0xc the waveform
  before FADE/DEP, +0x10 fade, +0x14 RAND's last phase, +0x18 DEST, +0x1c amount, +0x20 phase copy for the page,
  +0x24 stopped, +0x25 triggered; **+0x26/+0x27 are written by no stock code** (A's init `0x401375d4` clears +0..+0xc,
  +0x24, +0x25; B's flag setter `0x40137698` writes B's block only; dnfw's lfolength uses +0x27 as a free latch on 1.11). When a voice changes
  hands, A copies its LFO state from the track's other voice (the 40 bytes, from a snapshot at `0x4463fd18`).
- **The waveforms:** WAVE is read as a byte and **clamped to 0..6**; 0..5 call a function from the table
  `0x4020b7f8` (TRI `0x4013753e`, SINE, SQR, SAW, EXPO, RAMP) with the phase scaled to 32 bits; RAND (6) has its own
  code: a new value from the stock generator `0x4013767c` (an additive Fibonacci pair at `0x402a1338`) **16 times per
  cycle**, slewed by SPH (the SLEW table `0x4020b810`). The output x FADE x DEP (EMAC, fractional) is **added to
  row[DEST]** (DEST = the k in the same row, 0..100) and clamped to 0..0x7f00.
- **MODE** (0..4: FREE TRIG HOLD ONE HALF): TRIG/ONE/HALF reset the phase on a trig to SPH's start point; HOLD
  latches the output; ONE/HALF stop at the cycle's end/middle (the stop tables `0x4020b7a4/c0/dc`). FREE restarts only
  FADE on a trig. **SPH** = start phase, or SLEW on RAND (`SoundParameterSet::vslot22` switches the label only when
  WAVE == 6).
- **Note triggers:** the frame handler sets bit r of its trig mask (`-0x98(a6)`) when the voice's note record has
  the LFO-trig flag `0x400` (the trig's LFO.T), at `0x40026632` / `0x40026b84`.
- **Into the DSP:** the frame then copies the modulated rows into the SPI frame (k 25..65 from row +0x54 to slot
  +0xda, ...): the DSP gets the parameter word, one frame later.
- **Evaluator B, `FUN_401376bc`** (MIDI tracks): the same logic per track, called by the MIDI task `FUN_4012ac88`
  (on its tick for the MIDI-machine tracks in `0x4461827c`, and on a note with LFO trig), its own state at
  `0x44640498` (+0x26 is B's hold flag), a cycle of 21,600,000, DEST 1..8 (the MIDI track's row).
- **The page:** WAVE row `0x4f/0x59/0x63` (k 5, 13, 21; range 0..6; value text `0x400e3610`: TRI .. RAND, "ERR"
  past 6); the knob glyph `0x400bc4dc` and the page's big glyph `0x4010df62` both clamp the index to RAND's frame.
- **Pitch/tuning destinations** (descriptor rows, all LFO destinations by their modulation mask 0x1e00): WaveTone
  TUN1 (k 25), TUN2 (k 31), MAST (k 48), FM Drum TUNE (k 25), Swarmer TUNE (k 25): range 4..124, shown -60..+60, one
  unit per semitone [verified: format and range; dnfw docs: semitones]; FM Tone has no TUNE row, only the
  modulation-only **PITCH** ("Pitch All", k 50, 0..127, bipolar). The units of MAST and PITCH are **[inferred]**
  semitones (a sharcvm voice render to measure them did not give a clean tone in the time spent; section 8).

**Stop conditions: none holds.** No DSP change, no table growth (three existing rows' maximum and value text change;
param-grow copies the stock rows at boot, these with them), no storage change (WAVE stays the same u16 word).

**Community check** (memory community-sync): dnfw (DN2 1.11, AGPL, docs only) has `lfowaves` (STEP PULS NOIS TRAP
WTB1-3 after RAND, on hardware 2026-09-17), `lfolength`, `lfohold`, `lfo4`; **no Déjà vu on the Digitone II**. Their
docs agree with facts read here (evaluators A and B, +0x27 free, SPH's scale). The DT2 project is DT2-only.

## 2. Storage, MIDI, Overbridge

- **Kits [verified, `scripts/dj01_store.py`, `out/DJ01/store.json`]:** WAVE is the sound's u16 word k 5, 13, 21
  (stored ids 17, 18, 19 at stored sound +0x1c + 2 id); the sound serializer and loader copy the words, no clamp.
  On DJ01 the panel's value reached the live kit, the raw mirror and the working project image (the state a project
  save writes); 9, 12, 15 on all 48 WAVE words went through the kit serializer `FUN_400ddfa8` and loader
  `FUN_400dddb6` unchanged, and their value text reads PMAJ, WTON, OCTA. **A stock OS** (DT01's main OS, stock LFO
  code, from FL02's warm snapshot): its loader keeps 9, 12, 15, its value text says **ERR**, its evaluator plays each
  added wave **exactly as RAND** (`dj01_lfocheck.py --stock-os`, `out/DJ01/stockos.json`: every row word and the
  state block equal to WAVE 6 over 600 frames, every MODE, trigs), and a re-save writes the same sound records: the
  values survive a round trip through a stock OS. The page's glyphs clamp to RAND's; its SPH label stays SPH (the
  SLEW switch tests WAVE == 6). So **no storage change** and nothing a stock OS chokes on.
- **P-locks [verified]:** grid recording, WAVE locked on three trigs (`dj01-plock.script`): lanes (k 5, track 1)
  in the live pattern and (stored id 17, track 1) in the working image, values 0x0900, 0x0f00, 0x0800 (PMAJ, OCTA,
  DV-T); the locked labels draw the names. A lock is a u16 step value: 7..15 fit as any value.
- **Not saved:** the loops themselves (the values, the read positions). They are made at the first use after
  power-on; a project brings back WAVE/MODE/SPH, not the melody.
- **MIDI CC/NRPN in [verified: code read, emulator]:** `ParameterSet::vslot27` takes the CC value as the parameter
  value (`v << 8`), and the setter clamps it to the row's range: no scaling. Measured on CC 106 (LFO1 WAVE) on the
  auto channel: stock 0, 3, 6 -> TRI, SAW, RAND; 7..127 -> RAND (`out/DJ01/emu-dt01/`); DJ01 the same for 0..6,
  7..15 the added waves, 40 -> 15 (OCTA) where stock gives 6 (`dj01-midi-cc40.script`, live kit words). So 0..6 are
  unchanged, only values above 6 mean something new. NRPN 1:46/1:54/1:62 go the same way [inferred: same setter].
- **MIDI out [inferred]:** a knob turn sends the value as it is, so 7..15 go out on CC 106/115 (LFO3 WAVE has no
  CC) on a DV wave.
- **Overbridge [inferred]:** the OS sends a parameter change as the row's id and the 16-bit value (`0x400d5a54`); the
  plugin's own list has WAVE 0..6. A new wave set on the unit is outside the plugin's range (what it shows is
  unknown), and automating WAVE from the plugin can only set stock waves. Not testable here (no plugin).

## 3. Design (lfo-dejavu-dn2 0.1)

Behaviour (the Digitakt II guide's): WAVE 7 **DV-F**, 8 **DV-T**, 9..15 **PMAJ PMIN HIRA WTON DORI LYDI OCTA**
(the DT2 names, 4 characters like the stock ones). On these: MODE = loop length 2/4/8/16/32 (its words stay
FREE..HALF); SPH = mutation; SPD/MULT/FADE/DEP stock.

- **Our choices where the guide is silent:** the loop steps **16 times per LFO cycle**, at the phase's sixteenths, as
  the stock RAND takes new values (so SPD x MULT = 128 gives one value per 16th note, a 16-value loop = one bar).
  SPH 0..63 replaces the visited value with probability ((64 - SPH)/64)^2 (0 always, 32: 25 %, 48: 6 %); 65..127
  swaps it with a random place of the loop with probability ((SPH - 64)/63)^2 (96: 26 %, 127 always; the place may be
  itself); squared as the deja vu knob of Marbles, so the region near 64 is fine-grained. DV-T: a trig (LFO.T) sets
  the phase and the read position to 0 (the first value at once, the loop in time with the trig). The loop always
  steps forward (a negative SPD steps forward too). The scale rounding: the result of the stock add and clamp, in
  1/256 semitones from TUNE 0 (64), to the nearest note of the scale (ties down), kept inside 0..127.
- **Hooks** (`dv.s`, all checked against the stock bytes by `scripts/dj01_make_mod.py`): A: its call `0x400272d4`
  (counts frames), the WAVE clamp 6 -> 15 (2 bytes), the MODE read `0x40137b88` (MODE reads FREE on WAVE >= 7, so no
  stock trig mode, stop or hold applies), the waveform table `0x40137cda` (`dv_wtab_a`: the stock six, then our
  stub for 7..15), the add `0x40137d98` (the stock add and clamp, then the rounding on 9..15); B: the MODE/WAVE reads
  `0x40137770`, the clamp, the table `0x401378ce`. Rows 0x4f/0x59/0x63: max 15, value text `dv_fmt`.
- **State:** the loop's 32 values per **track** and LFO (`dv_loop_a[48]`, every voice of a track reads the same
  loop); the read position and step per **voice row** in the stock record's free +0x26/+0x27 (copied with the stock
  state when a voice changes hands); one mutation per step per loop even with several voices (a frame stamp).
  B: per track, its own arrays. Nothing saved: the loops are made at their first use.
- **Randomness:** xorshift32, one state for A (interrupt level) and one for B (the MIDI task). Seeded at its first
  use from a constant and the frame clock `0x80005398`, so the loops differ after each power-on; a test writes
  `dv_rng_a`/`dv_rng_b` for a fixed sequence (the harness does: every DV result below is deterministic per seed).
- **On stock waves** the only new work is two short stubs per LFO (MODE read, add): +482 instructions a frame.

## 5. Checks

- **Function harness** (`scripts/dj01_lfocheck.py`, `out/DJ01/lfocheck.json`, ALL OK): both images loaded as the
  boot leaves them, the evaluators called as their callers call them, MACSR fractional.
  1. **Stock waves = DT01's:** A, 3,000 frames of random settings (WAVE 0..6, every MODE, SPH, SPD, MULT, FADE, DEP,
     DEST but the WAVE words, random trigs, random base rows): every row word, the whole state block and the stock
     generator equal in every frame; DJ01 never wrote +0x26/+0x27 on stock waves. B, 3,000 calls the same. (An LFO
     aimed at another LFO's WAVE, k 5/13/21, can now reach the added waves: by design.)
  2. **DV-F, DV-T, the scale waves:** with SPH 64 the waveform's period is 2, 4, 8, 16, 32 steps for MODE 0..4 on
     each of DV-F, DV-T and PMAJ, every value the loop's; 16 steps per cycle (750 frames a cycle, 46.9 frames a
     step, the step index 0..15 in order); DV-T at three trigs (two 37 frames apart): position 0, phase 0, the first
     value, then position 1 at the next step, the loop unchanged; DV-F's position goes on through trigs. The same on B
     (a MIDI track, LFO3): the periods, the values `dv_loop_b`'s, DV-T's restart.
  3. **Mutation** (1,500 steps each, 16 values): SPH 0 replaced 100 % (want 100), 32: 25.0 % (25), 64: 0 (0),
     96: visible swaps 23.7 % (24.2 = 25.8 % x 15/16, a swap may pick its own place), 127: 93.9 % (93.75); no other
     change ever.
  4. **Scales:** `dv_scale` = the seven class sets; 80,640 results on the tuning rows (WaveTone TUN1, TUN2, MAST; FM
     Drum and Swarmer TUNE; FM Tone PITCH) across the seven scales, 16 rows with different knob values and depths:
     every one the scale note nearest the unrounded DV-F result (52,522 of them moved by the rounding); 134,400 results
     on other destinations and on the MIDI machine: DV-F's word for word.
  6. **A stock-LFO OS:** see section 2.
- **The booted OS** (`scripts/dj01-live.script` with the audio clock on DJ01 cold-booted, then

## 6. CPU cost of the main OS [verified, lfocheck.json "cost"]

Instructions per call of evaluator A (16 rows x 3 LFOs, Unicorn code-hook count; 1,500 calls a second):

| case | mean | worst frame |
|---|---:|---:|
| DT01, stock waves | 7,533 | 7,967 |
| DJ01, stock waves | 8,015 (+482, +6 %) | 8,449 |
| DJ01, all 48 LFOs DV-F/DV-T | 11,706 | 15,389 |
| DJ01, all 48 on a scale wave on TUN1 | 15,209 | 18,846 |
| DJ01, all 48 PMAJ on TUN1, SPH 127, every LFO stepping in the same frame | 15,441 | **20,274** |

So a DV LFO costs about 77 instructions a frame more than a stock wave (a scale wave on a tuning row about 150),
~0.12 M (0.22 M) instructions a second each; the extreme case (all 48 voice LFOs at once, all stepping in the same
frame) adds ~19 M instructions a second on the 250 MHz ColdFire, a few percent of it; stock waves cost +0.7 M. The
first version cost ~105 per DV LFO; a fast path (no new step: read the stored value, write nothing) brought it to
77. A frame between steps does one divu.l per DV LFO and no generator call.

## 8. Limits and open points

- **FM Tone PITCH and WaveTone MAST: semitones [inferred].** Both are bipolar modulation-only rows (0..127, 64 =
  0) without a page; TUN1/TUN2/TUNE are shown in semitones. A sharcvm render of one voice to measure them did not
  give a clean tone in the time spent. A 30-second check on the unit settles it (FLASH-DJ01.md asks for it); if wrong,
  one table entry (`dv_tune_k`) changes.
- **Poly voices:** every voice of a track reads the track's loop, each with its own position (copied from the
  track's other voice when it takes over, as stock copies the LFO state); one mutation per step even with several
  voices stepping in the same frame. With SPH below 64 two voices stepping at different times each renew a value.
- **The loop is not saved**; it is made after power-on from the frame clock, so each power-on gives other loops.
- **DV-T restarts the phase as well as the position** (so the first value sounds at the trig and the loop keeps time
  with it); the guide only says "the read position". SPH's curves are squared (the guide gives no curve). Both are
  ours; easy to change.
- **The emulator cannot show the LFO's effect on the sound** (no DSP voices, and its EMAC halves the smoother's and
  DEP's products): the checks read the waveform, the loops and the rounded parameter words.
- **Overbridge** (section 2) and **the 1.11 dnfw lfowaves mod** (their seven waves sit in the same WAVE values
  7..13 on 1.11): a project made with one is not meaningful on the other.
- **CPU** is measured in instructions (Unicorn), not cycles on the unit; the division per DV LFO and frame is a
  divu.l.
