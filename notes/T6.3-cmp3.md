## 1. What CMP3 is

**CMP3A's DSP on CP2F's layout** [verified, `out/T6.3/CMP3-dsp/build.json`, recipe `CMP3` in `tools/dspsplice/build.py`]:

| range | what | on the unit (CP2F) |
|---|---|---|
| `0x2dd600-0x2e1c36` | flanger, its glue, the stubs: byte for byte CMP2's / CP2F's | the same bytes |
| `0x2e1c40-0x2e23a8` | CmpSlot (FILL, 1,896 B, CMP3A's layout) | CmpSlot to `0x2e2370`, then watermark page 24, found intact |
| `0x2e2400-0x2e24d0` | CmpTail (FILL) | the same |
| `0x2e2800-0x2e2820` | **CmpMeter** (FILL, 32 B, new) | CmpLoad (FILL) |
| `0x2e2900-0x2e4f46` | code4: the glue, then cmp_tail.c (9,798 B) | code4 to `0x2e49c2`, then watermark page 23, found intact |
| `0x2e6000-0x2e6044` / `0x2e6800-0x2e686c` | constant data / stub save area | the same places |
| `0x300000-0x308400` | flanger state (FILL) | the same |
| `0x308400-0x30fd86` | code3: mbcomp.c (CMP3A's bytes) and the two stubs (only their two call targets differ) | code3 to `0x30ff76` |
| `0x310000-0x315f8c` | code2: the tape delay alone, byte for byte FTD1's / CMP2's / CP2F's | the same bytes |

Nothing of ours in `0x315f8c-0x318000`: a recipe key (`forbid`) makes the layout check and the final-image diff
refuse it [verified]. Dropped: heartbeat, breadcrumbs, probe switch, load meter, scanner, watermarks, page table,
comp-ui 0.1d's second bar. Sources: `fx/mbcomp.c`, `mbcomp.h`, `src/cmp_tail.c`, `.h` = CMP3A's (frozen copies in
`tools/dspsplice/src/cmp3a/`, recipe `CMP3A`); `src/cmp_glue.c` = CMP3A's + the meters.

**The meters** (`cmp_glue.c` `cmp_mtr`, a leaf, once per block per band): g = the band's gain reduction in dB at the
block's end (its y2; no makeup; also at MIX 0). Shown m: g >= m takes g at once and restarts a **hold of 750 blocks
(0.5 s)**; then m falls **0.01333 dB per block (20 dB/s)**, never below g; at most 25 dB. Half-word 8/9/10 = round(1310
x m). comp-ui 0.2's unchanged law h = q / 655 px makes that **2 px per dB** (1 px from 0.5 dB, the CMP box's 24 px =
12 dB, 50 px = 25 dB), so the ColdFire needed no change and the main OS stays CMP3A's. The bar hangs down from the
box's top edge (the bitmap's y points up). Half-word 11 keeps the stock meaning (deepest band now, `0x257c1c` in dB,
Q15 in +0x14's high half). A NaN, inf or out-of-range meter state reads as 0 / no hold. Cost +33..42 instructions per
block (0.01 %), stack unchanged (1,764 B) [verified, (d)].

## 3. Why the old meters "never moved"

In sharcvm the reported values are exact and large where the bands compress: on the test drums at the starting point
CMP1-CMP3A's Q15 law would have drawn up to 45 px (`hw11` in (b2)). So no code path loses them, and CP2D showed the
transport works on the unit. Left [inferred]: the bands were not compressing when looked at. CMP2 and CP2x start
with every band at RAT 1.00 (off), and LOW MUP stopped CMP2's DSP, which freezes the pages; CMP1 ran the bands from
each kit's hidden stock settings. Also unknown: the level inside the box on the unit. At THR 64 the bands only work
on peaks above -30 dBFS; drums 24 dB below the test level give 3 px on LOW and nothing else. FLASH-CMP3.md test 2
measures it (the THR at which each bar appears).

## 4. Limits

The meter shows peaks: on a busy pattern the bar can sit still for as long as hits come within 0.5 s. Below 0.5 dB
nothing is drawn (the Q15 law drew from 0.18 dB). The meter ignores the band's MIX and makeup. CMP3A's limits hold
(superseded note 5): old kits change sound (seeded, full-band); the stock MIX is on no page; with the sequencer
running, kit changes reach the DSP through the lazy recopy (unit check); exports and +Drive saves from a stock OS,
CMP2 or CP2F drop the band words; which UI actions send the vector change type is [inferred]; the constant check
word lets garbage through with p ~ 2^-16 (then clamped per word). That the power cycle restores a saved project's
values is [inferred] (the emulator's eMMC is empty: unit check, FLASH-CMP3.md 6).
