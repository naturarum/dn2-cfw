## Why 1.12 needed almost nothing

digikit resolves its guest addresses per image (`emu/symbols.py`): five RTOS entry
points at fixed addresses with their bytes checked, everything else by masked
signature or by operand from a resolved symbol. This is the fix for the
hardcoded-address bugs in `docs/DIGITONE.md` section 1. On 1.12 [verified]:

- All 7 REQUIRED symbols resolve: entry `0x400004e8`, task_start `0x40001314`,
  sem_pend `0x4000141a`, pend_call `0x401349b8`, completion_sem `0x4463fc4c`,
  depack_copy `0x40136968`, flash_read `0x401353ae`.
- Every optional symbol the harness uses outside trace-ui and diagnostics
  resolves. Examples: intro_done `0x400d3f70`, frame_sem `0x42c42614`,
  intro_pit3_isr `0x400d2ca4`, intro_park `0x400d3f9c`, mainloop `0x4002f178`,
  main_queue `0x4059e214`, display_start `0x40131ca4`, display_sem `0x4461f6e8`,
  panel_diff `0x40131fd2`, fb_front/fb_back `0x402a10c8`/`0x402a10cc`,
  set_pixel/get_pixel `0x40113e70`/`0x40113f3c`, sf_mulsf3 `0x40178904`,
  sd_bringup `0x4012be52`, current_tcb `0x4664bcdc`, ready_cursor `0x4058e15c`,
  uart8_tx_wait `0x4000221c`, panel_button_names `0x401f3c34`. Full table:
  `uv run python -m emu.symbols out/sections/dn2-1.12/section_3_MAIN_OS.bin`.
- Unresolved, the same as 1.11 per `tests/test_symbol_audit.py`'s allowlist:
  `transport` and `call_sites` (diagnostic only), plus `ui_key_dispatch`,
  `view_offer`, `view_activate`, `view_close`, `view_closed_mark`,
  `view_request_pop`, `view_sweep`, `ui_tick_inc` and `ui_tick_counter`. These
  are 1.15C `Fixed` addresses read only by `guirun --trace-ui`.
- Spot checks by disassembly (`m68k-elf-objdump -m m68k:cfv4e`): `mainloop`
  `0x4002f178` is `pea 0x4059e214; jsr 0x40001928; addq #4,sp; moveq #41,d1`, the
  1.11 shape (`moveq #41`). `display_start` `0x40131ca4` has the PIT3 base
  `0xfc08c000` and INTC `0xfc050050`/`0xfc05001d` literals. `intro_done`
  `0x400d3f70` clears PIT3 and posts `0x42c4261c`, then pends `0x42c42614`.
  `pend_call` `0x401349b8` is `jsr 0x4000141a; addq.l #8,sp;
  move.l #0x4463fc54,d0`. [verified]
- `emu.semscan.never_fake_semaphores` on 1.12 gives `{0x445f8474, 0x445f847c}`
  (bq_free_sem, bq_ready_sem). With PIT3 (vector 208) modelled it adds
  display_sem `0x4461f6e8` and frame_sem. This is the invariant
  `tests/test_semscan.py` checks on the other builds. [verified]
- Ladder rungs: the intro is live and not parked on frame_sem at 120M, 200M,
  280M and 400M. Vector 208 points at `0x400d2ca4` at every rung, so
  `emu.run.usable_rung` picks 400M, as on 1.11. At 60M the intro is not live
  yet. [verified]
- `emu.extract` (`dt2/elz.py`) gives sections 2, 3, 7 and 8 byte-identical to
  `ele3_out/` (sha256 of main OS `a098f620...`). Section 4 matches
  `03_type4.bin` minus its 8-byte header (`80000492 00000000`), which digikit
  strips. [verified]

## What I changed in vendor/digikit (branch dn2-1.12, uncommitted)

Diff: `out/T1.1/digikit-dn2-1.12.diff`.

1. `devices/digitone-ii.toml`: a `[[firmware]]` entry for 1.12 (sha256
   `7e5b8a73...ceb35`). This is how 1.11 was added (upstream commit `3f2a6b5`).
   Without it, `emu.device.identify` refuses the file, so `emu.gui` gets no
   control surface and `guirun --input` exits. [verified]
2. `tools/emucheck.py`: two optional, read-only outputs. `--png PATH` writes the
   frame emucheck judged, plus `<stem>-first.png` for the first main-screen frame.
   The new line "main screen first latched" gives the first timer step whose
   latched frame passes the main-screen threshold, counted from the snapshot and
   absolute. The watcher runs from `spin(on_chunk=...)`, which `spin` calls after
   each timer-deadline step, and it only reads the latched frame. So it moves no
   `emu_start` boundary and the instruction stream is unchanged. [verified: the
   upstream emucheck, with no watcher, run from a scratch copy, gives the same
   PASS line (600,008,000 instructions, frame_on 0.224365234375, satisfied 175)
   and the same six tasks; log in `out/T1.1/upstream-emucheck/`]
3. `tests/test_symbol_audit.py` and `tests/test_semscan.py`: run on
   `out/sections/dn2-1.12` when it exists, skipped otherwise, like 1.11. [verified]
4. `tests/test_machinepatch_plan.py`: a one-line fix for a bug already upstream.
   `_try_main_image` catches `Exception`, but `config.NotFound` subclasses
   `SystemExit`. So on a clone with no `sections/` and no `out/sections/dt2-1.15C`,
   pytest stops collecting with INTERNALERROR and no tests run.
   `issubclass(config.NotFound, Exception)` is False [verified]. It now catches
   `(Exception, config.NotFound)`.
5. `README.md`: a 1.12 row in the firmware table.
   `docs/findings/07-emulator.md`: a new section, "Digitone II 1.12 reaches the
   main screen with no address changes", with the marks digikit uses.

No emulator code changed: `emu/` is untouched. 1.11 and Digitakt II paths are
unaffected [inferred: the only runtime change is the read-only emucheck watcher].
The full non-slow suite passes: `958 passed, 99 skipped, 204 subtests passed`
[verified]. The opt-in `tests/test_checkpoint_digitone_real.py` passes on 1.12
(`1 passed in 107s`) [verified]. No 1.11 or Digitakt II firmware is in this
workspace, so the image-pinned tests for those builds skipped. Regression on
those images is not tested here.

## Warnings and traps

- **Patched Unicorn does not build on this Mac without pkg-config.**
  `tools/install-patched-unicorn.sh` fails in `qemu/include/qemu/int128.h:150`
  ("typedef redefinition with different types ('Int128' ... vs '__int128')").
  Cause: Unicorn's bundled QEMU `configure` stops at
  `pkg-config binary 'pkg-config' not found` (`qemu/configure:1251`) before its
  int128 probe, so `CONFIG_INT128` is never written and the fallback typedef
  clashes with clang's builtin. Fix without installing anything:
  `PKG_CONFIG=/usr/bin/false tools/install-patched-unicorn.sh`. configure honours
  `PKG_CONFIG` (`qemu/configure:343`) and the m68k build queries nothing through
  it. With that, `CONFIG_INT128 1` is in `config-host.h`, the library builds, and
  `emu.unicorn_compat` reports `compatible: true` on all four cases.
  Toolchain: Apple clang 21.0.0, SDK 27.0. [verified]
- **Keep 1.12 out of digikit's default `sections/`.** `emu.run --check` without
  `DT2_SECTIONS` extracts into `vendor/digikit/sections/`. While 1.12 sat there,
  `tests/test_machinepatch_plan.py` applied 1.15C anchors to it and failed
  (`0x400caf48 holds 008072012f03, expected 7206202f0004`). I removed that
  directory. Always pass `DT2_SECTIONS=out/sections/dn2-1.12` (or `--sections`).
  [verified]
- `emu.run` prints "only Digitakt II OS 1.15C has been tested" for any other file
  name, including 1.11. It is keyed on the file name and is harmless.
- `emu.run` without a snapshot argument looks for its ladder under
  `$DT2_SNAPSHOTS/Digitone_II_OS1_12/boot400M.snap`, not
  `out/snapshots/dn2-1.12/boot400M.snap`. Pass the snapshot explicitly. The GUI
  is not usable headless anyway: use `tools/guirun.py`.
- `uv sync` can put the stock Unicorn wheel back. If the emulator then refuses
  stock Unicorn, rerun the installer with `PKG_CONFIG=/usr/bin/false`.
- The Unicorn build prints `ld: warning: ignoring duplicate libraries: '-lm',
  'libunicorn-common.a'`. Harmless.

## Reproduce from a fresh clone

The El-Fw wrapper does all of this: `scripts/dn2-emu-112.sh all`, or one step at
a time with `setup`, `extract`, `ladder`, `check`. By hand:

```sh
git clone https://github.com/m-dwyer/digikit.git && cd digikit
git checkout 21b38b9 -b dn2-1.12
git apply out/T1.1/digikit-dn2-1.12.diff
SYX=elektron-firmware/Digitone_II_OS1_12.syx

uv sync
PKG_CONFIG=/usr/bin/false tools/install-patched-unicorn.sh   # see Warnings
uv run python -m emu.unicorn_compat                           # "compatible": true

uv run python -m emu.extract $SYX -o out/sections/dn2-1.12
DT2_SECTIONS=out/sections/dn2-1.12 uv run python -m emu.symbols \
  out/sections/dn2-1.12/section_3_MAIN_OS.bin
DT2_SECTIONS=out/sections/dn2-1.12 uv run python -m emu.run $SYX --check

mkdir -p out/snapshots/dn2-1.12
DT2_SECTIONS=out/sections/dn2-1.12 DT2_SNAPSHOTS=out/snapshots/dn2-1.12 \
  uv run python -m emu.checkpoint make \
  60000000,120000000,200000000,280000000,400000000 \
  out/snapshots/dn2-1.12/boot $SYX                            # ~7 min

uv run python tools/emucheck.py --device dn2 --syx $SYX \
  --sections out/sections/dn2-1.12 \
  --snapshot out/snapshots/dn2-1.12/boot400M.snap --instrs 600000000 \
  --png out/T1.1/main-screen.png   # ~5 min

# the GUI's configuration, headless, with PNGs at chosen counts
DT2_SECTIONS=out/sections/dn2-1.12 uv run python tools/guirun.py \
  out/snapshots/dn2-1.12/boot400M.snap --syx $SYX --limit 500000000 \
  --png-at 300M:out/T1.1/guirun-300M.png

uv run --with pytest python -m pytest tests -q
DT2_CHECKPOINT_REAL=1 DT2_DIGITONE_MAIN=out/sections/dn2-1.12/section_3_MAIN_OS.bin \
  DT2_DIGITONE_SNAPSHOT=out/snapshots/dn2-1.12/boot400M.snap DT2_DIGITONE_SYX=$SYX \
  DT2_SECTIONS=out/sections/dn2-1.12 \
  uv run --with pytest python -m pytest tests/test_checkpoint_digitone_real.py -q
```

## Open problems

- The panel code mapping (`devices/digitone-ii.toml` `[panel]`) was measured on
  an earlier Digitone build and is not re-measured on 1.12.
  `tools/panelsweep.py` would check it before T2.4 or anything that presses keys.
- `tools/machineprofile.py` has no 1.12 profile, so `machinebuild.py` and
  `machinecheck.py` do not support 1.12. Not needed for T1.1.
- The trace-ui symbols (`ui_key_dispatch`, `view_*`, `ui_tick_inc`) are still
  1.15C `Fixed` addresses, unresolved on 1.11, 1.16 and 1.12. So
  `guirun --trace-ui` gives no UI trace on 1.12. Fixing that needs a signature
  per symbol.
- `transport`/`call_sites` are unresolved (diagnostic-only, as on every Digitone
  build).
- No 1.11 or Digitakt II image here, so this workspace cannot re-run their
  image-pinned regression. Run them where those images exist before an upstream
  PR (digikit's contributor notes ask for `pytest --slow` before a commit).
- emucheck's main-screen test is a lit-pixel threshold (>= 0.12). The PNG was
  checked by eye here. A dialog that lights more than 12% of the panel would pass.
