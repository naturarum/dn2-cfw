# R1.15: the web patcher

2026-10-30. The owner, after a Reddit comment asked for one: "Can we do that?", then "ok let's build the web patcher
with javascript". Marks: **[verified]** = run here; **[inferred]** = reasoned. Nothing published.

## What it is

`tools/patcher/web/`: Digiwerk Patcher as a static page. The user picks the four slots, drops Elektron's
`Digitone_II_OS1.12_dist.zip` (or the `.syx` inside), and the page makes the build on their computer and saves it.
Nothing is uploaded; the page fetches only our pack for the chosen build (only our bytes: stockcheck.py). Windows and
Linux users get a patcher, and nothing needs notarizing.

- `dn2patch.js`: the C core (`../dn2patch.c`) ported line for line: SHA-256 and HMAC, the codec walker (depack and
  rebuild), the stock reader, the seal key, the pack reader, the ops, the rebuild, the C core's messages.
- `unzip.js`: the `.syx` inside Elektron's `.zip`, through the central directory, inflated with the browser's
  DecompressionStream (deflate-raw); macOS's `__MACOSX/` entries skipped.
- `model.js`: the app's rules (Catalog.swift, Model.swift): slots, tiles (picked, built, not built, won't fit), the
  name of a combination, the DSP note, the record line.
- `art.js`: the pixel art from `docs/identity/*.svg` and the app's glyphs, on canvases at whole device pixels.
- `app.js`, `index.html`, `style.css`: the app's window (ContentView.swift, ManualView.swift): BUILD and MANUAL,
  the base strip, the slots, the status box with the DSP meter, the three steps, the status bar. Differences: "Save
  ID.syx" instead of "Show in Finder" (the build is also saved once when made), "Get Transfer" instead of "Open
  Transfer", "made in your browser ... Nothing is uploaded"; a file dropped anywhere on the page counts. Narrow
  screens: two slot columns, then one; the header wraps.
- `build.mjs`: the site in `out/patcher/web/`: the files, `identity/`, `packs/ID.dn2p` (from `out/patcher/ID/patch.bin`),
  `catalog.json`, `dsp-budget.json`, and `index.json` (each pack's fields, read from the pack by `dn2patch.js`, with
  the pack's own sha256: the page refuses a pack that isn't the one listed). It refuses to write unless every pack
  rebuilds its tested build here and the catalog covers the packs.

## Checks [verified]

- `node tools/patcher/web/test.mjs`: all fourteen 0.2.0 builds (the six spring builds 0.2.1 withdrew included) byte for byte from Elektron's `.syx` and from its
  `.zip` (about 0.1 s each in Node); each pack's fields; the build itself recognised; refused with the C core's
  message and no output: a truncated 1.12, a text file, a zip without the file, OS 1.11, another build, the build
  itself; a corrupted pack hands nothing over.
- `node tools/patcher/web/test-model.mjs` (after build.mjs): the packs' effects match their names, base 0.2 in all,
  the catalog covers them one per combination, the 16 combinations (since 2026-10-31 the site carries 0.2.1's eight:
  8 built, the spring's 6 not built, CMP3+TAPE+SPNG and all four won't fit), CFTE's spring tile WON'T FIT and its
  note "With the spring too: 99.3 KB, won't fit", CFEE's spring tile NOT BUILT, EEEE, the records.
- In the browser pane (Chromium, 1100 px and 375 px): the page opens on CFEE; picking TAPE ECHO shows CFTE; a drop of
  Elektron's real `.zip` (served from this Mac to this Mac only) made CFTE.syx, and the saved file is 2,447,648 bytes,
  sha256 `eafa99b3...`, CFTE's; a dropped CFEE.syx is refused and Save turns off; the MANUAL page; no sideways
  scrolling at 375 px.
