# T2.4a test: independent check of live keyboard control (Digitone II 1.12 emulator)

Date: 2026-10-05. Independent tester of T2.4a (builder's report:
`notes/T2.4a-live-control.md`). Data in `out/T2.4a-test/`.

## Progress

- [x] Read the builder's note, emu/live.py, LIVE.md, launcher, tests.
- [x] Panel code map for 1.12 checked from the image bytes (independent of panelsweep).
- [x] Every key of the map driven through KeyInput, headless, via the launcher: 121 runs, before/after PNGs.
- [x] FUNC / TRK holds, encoders both ways, press-and-turn, firmware auto-repeat, copy/paste.
- [x] The real Tk window driven on this Mac (Tk 9.0.3, Swiss French layout): found that a third of the map was dead.

## Verdict

**Holds with corrections.** The headless path (KeyInput -> inbox -> UART8 panel
bytes -> firmware) works for every key and both encoder directions, and the
panel code map is right for 1.12. But the window, which is what the user will
actually use, was broken on this Mac: under the Tk the launcher runs (9.0.3)
and the user's keyboard layout (Swiss French), 11 of the 54 panel buttons had
no working key and TRK worked only as Shift+Tab, all 9 encoder-left turns and
`?` did nothing, and two letter
keys were swapped (the key right of T opened KEYBOARD mode instead of TRIG 6).
The builder never sent a real Tk event: its window check called the handlers
with hand-written keysyms. Fixed in `emu/live.py` (below); after the fix every
physical key maps as documented, proven end to end in the window with the
emulator running. A person still has to press real keys once (dead keys,
macOS press-and-hold: see "For the user").

## Bugs found and what I changed

All in the builder's new files. Originals kept for diffing:
`out/T2.4a-test/live.py.orig`, `dn2-live.sh.orig`, `LIVE.md.orig`,
`test_live_keys.py.orig`.

### 1. Window: punctuation keys, Shift+digit and the user's layout were dead (major) [verified]

- **Tk 9 keysyms are characters.** The launcher's Python has Tk 9.0.3
  (`tkinter.TkVersion` 9.0, `aqua`). Its `%K` for the comma key is `,`
  (keysym number 44), not `comma`; Shift+1 is `!`, not `exclam`
  (`out/T2.4a-test/harness/`, probe output in `out/T2.4a-test/tk/tkkeys-swissfrench.txt`).
  `DEFAULT_KEYS` and the `SHIFTED` fold table use the Tk 8 names, so on any
  layout `[ ] ; ' , . / - = \` `` ` `` (FLTR, AMP, MOD, PAGE, PTN, SONG, TEMPO,
  PLAY, STOP, LEVEL push, SETTINGS) and every Shift+digit could never match.
- **The user's layout is Swiss French** (`com.apple.keylayout.SwissFrench`,
  QWERTZ). There the US punctuation positions type è ü ¨ é à $ < § ^ ' -,
  Shift+1..9 type `+ " * ç % & / ( )`, and Y/Z are swapped.
- **Measured, original code** (`out/T2.4a-test/tk/tkmap-orig.txt`): every
  physical key sent through the real `LiveApp` bindings with
  `event generate -keycode (vk<<24)`. Tk derives the keysym from the virtual
  key and the active layout exactly as for a real key press (vk `0x21` gives
  `è`, with Shift `ü`). Dead: FLTR, AMP, MOD, PAGE, PTN, SONG, TEMPO, PLAY,
  STOP, SETTINGS, LEVEL push, plain Tab (TRK), encoder A-H and LEVEL left (all 9), `?`.
  Wrong: the key right of T (Z on QWERTZ) -> KEYBOARD instead of TRIG 6, and
  the key at US Z (Y on QWERTZ) -> TRIG 6 instead of KEYBOARD.
  Worked: letters (except that swap), digits right, Space, Return, Delete,
  Esc, arrows, F1-F8, keypad.
- **A stuck button too:** with keysym matching, a key's release could carry a
  different keysym than its press (hold `,`, press Shift, let go: `;`), so the
  release was never sent.
- **Fix** (`emu/live.py`): new `MAC_VK` (Carbon virtual key code -> the US key
  name at that position), `CHAR_KEYSYMS` (Tk 9 characters -> names) and
  `event_key(keysym, keycode, state)`. `LiveApp._key_down/_key_up` now call
  `event_key`: on macOS the key is the physical one (`keycode >> 24`), so the
  map is the same on every layout and a release always matches its press;
  Shift comes from the event state; `?` (whatever key types it) is help;
  elsewhere the keysym is used with Tk 9 characters renamed. The ISO key left
  of 1 (§, vk `0x0A`) is also SETTINGS. KeyMap, KeyInput, `--keymap`, the
  headless path are unchanged.
- **After the fix** (`out/T2.4a-test/tk/tkmap-fixed.txt`): every physical key,
  with and without Shift, sends exactly what the key map table says; Shift+1..9
  turn encoders A-H and LEVEL left.

### 2. Window: plain Tab never reached the key handler [verified]

Tk 9 binds Tab on `all` to the virtual event `<<NextWindow>>`, and that
binding wins over the builder's `bind_all('<Tab>')`; only Shift+Tab worked.
So TRK could not be held from the keyboard. Fix: `LiveApp.__init__` deletes the
`<<NextWindow>>` and `<<PrevWindow>>` virtual events. Checked: plain Tab now
holds TRK (`tk/fixed-03tab-held.png`, the SYN box inverts as on TRK hold).

### 3. Window: `--save` was ignored [verified]

`main()` passed `--save` only to the headless `LiveEmulator`; `LiveApp` had no
such option, so `scripts/dn2-live.sh --save x.snap` (as documented) saved
nothing when the window closed. Fix: `LiveApp(..., save_at_exit=)` passed to
the worker, and `quit_all` waits for the worker (up to 60 s when saving) so
the process does not exit mid-write. Checked: a window closed with
`quit_all` wrote `out/T2.4a-test/tk/tk-quit-save.snap` (2.7 MB).

### 4. Launcher: relative paths resolved inside vendor/digikit [verified]

`scripts/dn2-live.sh` `cd`s into `vendor/digikit`, so
`scripts/dn2-live.sh --script keys.txt` failed (`FileNotFoundError`) and
`--save x.snap`, `--out`, `--report`, `--keymap`, `DN2_SNAP=x.snap` all
pointed into vendor/digikit. Fix: the launcher makes those paths absolute
against the caller's directory first. All 121+ runs of this test went
through the fixed launcher with relative paths.

### Tests and docs

- `tests/test_live_keys.py`: 3 tests added (position mapping with Swiss French

## Panel code map for 1.12 [verified: image bytes]

Checked statically, not with panelsweep: the panel driver `FUN_4011fc8c`
(reads DTCN0, emits the 16-byte records through `FUN_40001896`) turns
(channel, bit) into a code with `code = [0x401f3dec + 4*(channel*8 + bit)]`.
That table in the 1.12 image:

| channel | bits 0-7 -> code |
|---|---|
| 0-5 | channel*8 + bit + 1 (codes 1-48) |
| 6 | 50, 49, 0, 0, 51, 52, 53, 54 |

Identical to `devices/digitone-ii.toml` `[panel]` and to the builder's
panelsweep JSON. The name tables (`0x401f3c34` buttons 0-54, `0x401f3bc0`
encoders 0-9) read back exactly as in the builder's table. The encoder index
the views use is `code - 1` for A-H (`FUN_401133ae`) and 8 for LEVEL, so the
detent hook's `channel == enc` assumption holds in `ParameterPageView::vslot17`;
other views fall back to "the only pending detent".
Which *physical* key sits on each (channel, bit) cannot be checked without
the unit; the firmware's own names are the authority here.

## Builder's claims

Confirmed:
- Panel map = devices/digitone-ii.toml for 1.12 (and from the image's own table).
- Headless: every key through KeyInput reaches the firmware and does what the
  OS draws for it; FUNC and TRK chords work; encoders one step per press, both
  ways; press-and-turn; the sweep table in the builder's note matches mine
  key for key.
- Speed: real-time pacing 1.00x in 50 of 57 runs (0.96-1.02x in the rest, 6
  runs in parallel); snapshot load and first frame 0.7 s.
- Latency: median of the per-run medians 51 ms over 101 runs (builder 52 ms);
  but the tail is longer than the "22-146 ms" quoted: p90 244 ms, max 362 ms
  (the first press after start, 6 emulators sharing the Mac).
- DTIM0: the main OS only reads DTCN0 (8 sites); the image has no other
  `0xFC0700xx` word except two in graphics data at `0x402b6dc6`/`0x402b6e06`;
  the bootstrap has no DTIM0 reference.
- Encoder filter: `FUN_4011364e` reads divisor at cfg+4+4 (or +0x10+4
  pushed), state from `FUN_40113626` = handler+0x20+0x14*n (n<10) as the hook assumes.
- PLAY: no visible change 1 s after PLAY (A34); sequencer not running.

Refuted or wrong:
- "Every key ... has a Mac key", "Shift + digit is folded back with a US
  table", "Tab = TRK hold": false in the actual window under Tk 9 (any layout)
  and on the user's Swiss French layout (bug 1, 2). Fixed.
- "`--save PATH` stores the state when the window closes": only headless (bug 3). Fixed.
- "In the window itself ... FUNC + FLTR opened SETUP": it was the handlers
  called with the keysym `bracketleft`, which Tk 9 never produces.
- Launcher examples with relative paths did not work (bug 4). Fixed.

## For the user (not checkable here)

To try on the Mac with real keys, after these fixes:
- `scripts/dn2-live.sh`, then press `?`: the map is by key position as on a US
  keyboard. On the Swiss French keyboard: FLTR = è, AMP = ¨, MOD = é,
  PAGE = à, LEVEL push = $, PLAY = ', STOP = ^, TEMPO = -, SETTINGS = < or §,
  TRIG 6 = Z, KEYBOARD = Y.
- ^ and ¨ are dead keys on Swiss French. If STOP (^) or AMP (¨) do nothing,
  that is macOS holding the accent; tell the agent and they get other keys.
- macOS press-and-hold: holding a letter (a trig) may open the accent popup
  instead of holding the key, which would break "hold a trig + turn an
  encoder". If so: `defaults write -g ApplePressAndHoldEnabled -bool false`,
  then restart the window.
- F1-F8 need fn on a laptop keyboard unless "Use F1, F2, etc. keys as
  standard function keys" is on.
- On the unit: does an encoder's value stay shown after you press and release
  it (as in the emulator), or does the label come back?
- Close the window with Cmd-Q or the close box; `--save x.snap` then keeps
  the state.

## Missed by the builder (not fixed)

- Double taps faster than 40 ms between release and next press are merged
  into one press (KeyInput's release delay); only matters for very fast
  repeated taps of one key [inferred from the code].
- Focus is checked with `<FocusOut>` on the toplevel, which also fires when
  focus moves between widgets inside the window; harmless today because no
  widget takes focus [inferred].
