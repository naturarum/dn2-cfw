# T2.4b: the audio clock in the emulator, so PLAY runs the sequencer (Digitone II OS 1.12)

Date: 2026-10-05. digikit branch `dn2-1.12`, commit `c9ca85b`. Marks: **[verified]** = measured in the
emulator or read from the bytes; **[inferred]** = reasoned.

## Result

`scripts/dn2-live.sh --ssi0-hz --ips 150e6` (or `emu.live ... --ssi0-hz --ips 150e6`) runs the
sequencer. With the warm snapshot's project at **81.0 BPM** (on screen), the sequencer position
advances **5.4 steps per second of emulated audio**, which is 81 BPM in sixteenths. **[verified]**
Trig LED messages change while playing and stop after STOP. **[verified]** Cost: 0.1-0.2x real time
with the clock on, against 1.95x without. Fine for testing sequencer and arp mods, too slow to play.

## The chain on Digitone II 1.12 (all [verified] from the bytes and the run)

1. **SSI0 + eDMA 48 (RX) / 50 (TX).** The descriptors in the warm snapshot are the shape digikit's
   `emu/ssi.py` expects: 32-byte minors, 64 minors per major loop, scatter/gather between two banks.
   RX banks: `0x4e6e7100` and `0x4e6e7900`, 32 rows of 64 bytes each (16 slots of 32 bits).
2. **Vector 170** = `0x400d55d4`, the generic handler. It scans the RX bank just filled for the
   SHARC's sync word `0x007fffff` at a row head. If it is at row 0, it counts (`0x42c4caec`); after
   more than 63 aligned blocks it installs the pending handlers `0x42c4caf8` -> vector 168 slot and
   `0x42c4caf4` -> vector 170 slot. Otherwise it shortens the next major loop (62 minors) to realign.
3. **The real channel-50 ISR** `0x40025386`: stamps DTIM2 (`0xfc07800c`) into `0x4664c1b8`, counts
   blocks in `0x4664bf48`, sets `0x4058f540 = 1`, clears CINT 50 and sets INTFRCH1 bit 31 at
   `0x400253c4` (source 63, **vector 191**). digikit's symbol `ssi0_dma_force_rte` resolves to its
   `rte` at `0x400253ce`.
4. **Vector 191** = `0x40025e36`, the frame handler (T3.3). It sets INTFRCH0 bit 12 at `0x40027afc`
   (source 44, **vector 108**, the sequencer clock `0x400d79c8`), which sets INTFRCH0 bit 25 at
   `0x400d7d66` (source 57, **vector 121**, the step handler `0x400d99de`) (T2.2).
5. The step handler adds 900,000 to the sequencer position `0x42c4f900` per sub-step (6 per step).
   The clock `0x80005398` advances by 2 x `[0x402a132c]` per frame; `[0x402a132c]` = 9,720 = 120 x BPM.

## Rate

96,000 SSI requests per second. Two 32-byte minors make one 64-byte row, so 48,000 rows per
second (one row per sample frame at 48 kHz [inferred]), and one 64-minor major loop = 32 rows = one
32-sample block: **1,500 blocks per second**, the SHARC's own block rate (T3.4, T3.2). The tempo
check above confirms it: at any other rate the measured tempo would not match the screen.
T3.2 independently found SPORT0 A/B on the SHARC to be a 16-slot TDM link, which fits 16 slots per row.

## What changed in digikit (`dn2-1.12`)

- `emu/live.py`: `--ssi0-hz` (bare = 96,000), `--ips`, `--no-dsp-sync`; plants the sync word in
  both RX banks; counts vectors 170/191 and forced interrupts in the summary.
- `emu/ssi.py`: `per_event` batching (one event per major loop); one contiguous read per TX minor.
- `emu/intfrc.py` (new): software-forced interrupts, level-sensitive, delivered after every `rte`
  (new `Machine.after_rte` hook in `emu/harness.py`) and at spin() step boundaries. Vector 191 stays
  with `emu/ssi.py`.
- `emu/harness.py`: BITREV and BYTEREV (ISA_C). Unicorn raised vector 4 on BITREV at `0x4002aa80`
  as soon as the sequencer played; the firmware then showed its EXCEPTION screen (reporter
  `0x4011ed4a`, "EXCEPTION DS%.04s" / "V%02x M%x P%08x") and halted.
- `--ips`: the default emulated CPU rate (4 x 4.68M) is too low for 1,500 frame interrupts a
  second: CPU load 100%, the UI never redraws. At 150M (the MCF54418 runs at 250 MHz) load is ~20%.
- Tests: `tests/test_intfrc.py` (9). Full suite: 978 passed, 99 skipped.

## Method

`scripts/t24b_probe.py` reads the vector slots, INTC and eDMA state of a snapshot.
`scripts/t24b_debug.py` wraps `emu.live`: it catches the EXCEPTION reporter, logs vectors, dumps
UART8 bytes per screenshot and times the step handler. Runs in `out/T2.4b/run1`-`run7`
(`play.script`, `play-long.script`).

## Open

- **Speed.** 0.1-0.2x real time with the clock on. The guest's busy work is about 30M instructions
  per emulated second (20% of 150M), which Unicorn could run faster than that; the per-block
  Python work (1,500 step boundaries a second, hooks, delivery) is the likely limit. Not profiled.
- **The RX data is silence apart from the sync word.** Whatever else the SHARC sends on that link
  (possibly the audio for Overbridge/USB [inferred]) reads as zeros.
- **MIDI out** is still not connected (T2.4, part two), so the sequencer's MIDI notes can't be
  heard or checked yet. That is the next step for testing the arp and MIDI-polyphony mods.
- Snapshots saved with `--save` while the clock runs carry the SSI component; not yet tried.
