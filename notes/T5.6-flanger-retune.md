# T5.6: the flanger retune, one knob from phaser-like to chorus

2026-10-22. Owner: option (a), "a continuous effect that uses the same controls (effectively no new code just
different ranges)", "improving it without increasing mem/cpu load". Planned and measured; **built as FL01**
(OB01 + this retune, section 6). **On the unit 2026-10-23: "seems to be working very well."**

## 1. What the unit's flanger can do today [verified]

The flanger (`fx/flanger.c`, twelve knobs) sits in the chorus slot and gets only the stock chorus page's four
knobs, A DPTH, B SPD, C HPF, D WDTH (frame words k25..k28; `tools/dspsplice/src/flg_glue.c`, notes/T3.8 5.1). The
rest is fixed: **MAN 50 (centre 0.9 ms), FDBK 107 (+68 %)**, DAMP 12, sine, no SLEW/SYNC/OFS/POL. So on FLG1 to CMP4:

- **the centre delay never moves:** 0.9 ms, first notch 554 Hz, 18 notches below 20 kHz. A chorus (10-30 ms, little
  feedback) and the short end (a few notches, phaser-like) cannot be reached. The chorus and slapback renders of
  the A/B page use MAN and FDBK, which the unit does not have;
- **DPTH** is linear, 0.026 octave per step: fine for flanging (1-3 octaves), coarse for a chorus (0.05-0.3 octave);
- **WDTH 127, the stock default of a new kit, plays both sides in phase** [sharcvm; not checked on the unit]:
  the right LFO's offset is half a cycle, 2^31 in the 32-bit phase; selcc converts float to uint32 with a signed
  `TRUNC`, which overflows there, and with MODE1's ALUSAT off (the DN2's DSP state, 0x1011800) the result is all
  ones, an offset of about 0. WDTH 126 is 177 degrees. sharcvm against the Mac build: bit-identical at WDTH 0-126,
  the right channel off at 127; at 127 SHARC's right channel equals the Mac's at WDTH 0 within 2.8e-6. **On CMP4
  this can be heard:** WDTH 126 sweeps wide, 127 narrow.
- Stock defaults of a new kit's chorus rows (k25..k28, parameter table group 16): DPTH 127, SPD 32, HPF 0, WDTH 127.

The short end against a phaser [inferred]: with dry and wet at unity the comb's notches sit at (2k+1)/(2d). A
4- to 8-stage phaser has 2 to 4 notches; the comb has that many only below about d = 0.2 ms, where they sit at
2.5-20 kHz. So the short end is an airy, high phaser-like sweep (few, wide notches moving together), not the
mid-range swoosh of a Phase 90 (its notches at a few hundred Hz to 2-3 kHz, unevenly spaced). A real phaser needs
all-pass stages: new code, which the owner did not want.

## 4. Old kits [inferred from the map]

The kit stores the same four values; only C's meaning changes:

- **C at 32** (the swell patch's HPF): exactly as on CMP4.
- **C at 0, the stock default** (likely most kits, if HPF was never touched): the shortest, phaser-like end (0.05 ms)
  instead of the 0.9 ms flanger, and the wet path's low cut goes from 20 Hz to 64 Hz. Below 32 it is shorter and
  brighter, from 33 to 64 a longer flanger, above 64 towards the chorus. Set C to 32 to get the CMP4 sound back.
- **WDTH 127** (the stock default) now sweeps the two sides 180 degrees apart instead of together: wider.
- DPTH and SPD keep their sound up to TIME 64.
- Options for the release (main OS, data only): label C "TIME" (a string, as flanger-names does for the page), and
  maybe C's default 32 for new kits so they start as the flanger (parameter table group 16, k27, row default 0 now).

## 7. FL02: the speed in sync with the tempo, FUNC + turn as on the delay (2026-10-23) [verified unless marked]

Owner, 2026-10-23: "do you think we could sync the flanger speed to the tempo using FUNC + turning the encoder just
like we do on the delay?" Built into **FL02** (`out/FL02/FL02.syx`; with the compressor glyphs, notes/FL02.md).

### 7.1 How the stock OS does it

- **FUNC + turn is one function per row, in the display entry** (not a row flag, a step table in the descriptor or a
  display type). `ParameterPageView::vslot17` (`0x40067470`, the encoder) passes "FUNC held" (`FUN_4011fac4(0x11)`)
  to the parameter set's slot 11, `ParameterSet::vslot11` (`0x4003780e`). With FUNC it calls the row's display entry
  (`0x4243425c + 0x44 x row`) +0x34, a std::function (manager +0x3c, invoker +0x40), as
  `(functor, value, delta, min, max, default) -> value`, then sets that value (clamped, `0x40037326`). Without FUNC
  slot 8 adds the encoder's delta: SPD moves by whole steps (`0x100`) and keeps the low byte [verified: decompile,
  disassembly, and an emulator write trace of k 32 (PC `0x40037df8` < `0x40037326` < `vslot22` < `vslot17`)].
- The functions: most rows `0x400bbd20` (delta < 0: the minimum, else the maximum; **the stock SPD jumps to 0 or 127**,
  emulator: 0x2505 -> 0x7f00 -> 0x0000), MUP `0x400bbd32` (the default), FDBK `0x400bbd38`, WID `0x400bbddc` (the
  centre), the LFO speeds `0x400cba2a`, and **the delay's TIME `0x400cb992`**: the next or previous of the 14 note values
  its value text `0x400e3e7a` names (1/128, 1/64, 1/64., 1/32, 1/32., 1/16, 1/16., 1/8, 1/8., 1/4, 1/4., 1/2, 1/2., 1/1 =
  TIME 0, 1, 2, 3, 5, 7, 11, 15, 23, 31, 47, 63, 95, 127; any other TIME prints as its number). Emulator
  (`scripts/fl02-delay.script`): TIME 0x2f02 "48.00", FUNC + right 0x3f00 "1/2", 0x5f00 "1/2.", FUNC + left 0x3f00.
- **The delay has no mode**: every TIME is tempo-relative ((v + 1)/128 note), FUNC only snaps to musical values. The
  flanger's SPD is a free rate, so a synced speed has to be told apart in the value itself.
- **The tempo**: frame word `0xd8` = round(120 x BPM); the DSP's unpack puts BPM (float) in the FX bus descriptor
  +0x14, which the stock delay reads (`tools/dspsplice/src/fxio.h`, T3.4).
- The display table is built at boot by the static initializer `0x400c2c4e`, which copies each row's +0x34 from a
  template std::function; for row 0x6a (SPD) at `0x400c5c96`: `pea 0x42432ee8` (the shared template), `pea 0x42435eb8`
  (the entry +0x34), `jsr (a4)` (std::function's copy constructor `0x401adfb2`, which copies +8 and +0xc and has the
  manager clone the functor).
- `fx/flanger.c` already had FL_SYNC (0 free, 1..12 = 16, 8, 4, 2, 1 bars, 1/2, 1/4., 1/4, 1/8., 1/8, 1/16, 1/32) and
  `flanger_set_bpm`; FL01's glue never called them (sync off, 120 BPM).
- **Storage**: the FX record's serializer `0x400dcf34` and loader `0x400dcef0` copy the 16-bit live words as they are
  (k 26 = stored id 2, record +8); the ColdFire's smoother settles the frame word exactly on any 16-bit target (its
  arithmetic, T3.3: word = (state + 0x8000) >> 16, the state's error decays to under 34/65536; checked for the 12
  values below from 8 starts each: settled in at most 363 frames, 242 ms).

### 7.2 The design: the sync lives in SPD's own value

- **A synced speed is a low byte**: S(i) = (a_i << 8) | i, i = FL_SYNC 1..12, a_i = 9, 23, 37, 52, 66, 80, 86, 94, 100,
  108, 122, 126 (the free SPD closest to that division at 120 BPM; 126 for 1/32, whose 16 Hz is above the free top):
  0x0901 16/1, 0x1702 8/1, 0x2503 4/1, 0x3404 2/1, 0x4205 1/1, 0x5006 1/2, 0x5607 1/4., 0x5e08 1/4, 0x6409 1/8.,
  0x6c0a 1/8, 0x7a0b 1/16, 0x7e0c 1/32. Every other value is a free speed with FL01's law. The kit stores the row's
  value only, as before; nothing else is stored.
- **Old kits**: the stock UI, MIDI CC and FL01 make whole numbers (low byte 0; FL01's FUNC + turn: 0 or 127), never an
  S(i), so an old kit plays exactly as on FL01.
- **Main OS, `flanger-sync-dn2` 0.1** (fork, `scripts/fl02_make_mod.py`; 413 B): row 0x6a's value text (descriptor +0x34
  -> `fls_fmt`: the 12 names, the stock plain number otherwise) and its FUNC + turn function (`0x400c5c96`
  `pea fls_tpl`: the entry is copied from our template, the stock manager `0x400bfbec` with `fls_func`). `fls_func`:
  from S(i) one division faster (right) or slower (left), held at the ends as the delay is; from a free value the first
  S above it (right) or the last below it (left).
- A turn without FUNC from S(i) steps the number and keeps the low byte: (a_i +- k) << 8 | i is a free speed (at most
  0.047 of a step above the number shown); back on a_i it is S(i), synced again.
- **DSP, recipe FL02**: `flg_glue3.c` (FL01's glue; SPD goes to `flg_spd` when it moves, and every block while synced or
  waiting) in FL01's place in block 1 (`0x2e15d4-0x2e1c2e`, 1,626 B, under the proven `0x2e1c36`; flg_init and
  flg_process at FL01's addresses, so the stubs are FL01's bytes), and `flg_sync.c` (`flg_decode`, `flg_spd`, 1,206 B) in
  code2 at `0x310000-0x3104b6`, inside the proven `0x310000-0x315f8c` (FTD1 to CMP3's tape delay; not loaded on FL01).
  `flg_spd` reads the word whole (w = p x 32512 + 0.5: exact for all 32,768 words), compares it with the 12 values (no
  table, for selcc), and plays a new S(i) only after the word has held it **48 blocks** (32 ms): a glide of the smoother
  sits on a word it passes for at most 37 frames (the word just above a whole number it settles on, e.g. 0x0901 on the
  way down to 9), so a free knob never syncs by accident. Synced: FL_SYNC i and the tempo (clamped 30..300 BPM) when
  either changes. Free: FL01's call, `flanger_set(s, FL_SPD, v)`, and FL_SYNC back to 0. The slot is FL01's
  (`flg_slot3.h`; its unused counter is now the sync field), magic `FLG3`. `fx/flanger.c` is unchanged.
- **Not in this build**: the sweep's phase is not reset at the bar (the period follows the tempo, the start does not);
  the Overbridge plugin shows the anchor number [inferred]; the knob's dial points at a_i.
