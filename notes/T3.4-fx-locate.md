## Summary

All four effects are found, and each one is tied to its parameters by dataflow, not by guesswork:
the frame word goes to a float in a parameter struct, and that struct's address is passed to exactly
one routine. Each routine also has the structure you would expect. **[verified]** for the dataflow and
the calls. The labels below follow from that. A name is **[inferred]** only where noted.

| effect | entry (call site) | params (frame -> struct) | state and buffers | rough cost / block |
|---|---|---|---|---|
| Chorus | `0xb84d5c` (call `0x1c1be1`) | `0x9fa`-`0xa00` -> `0x257950` | DDR `0x80459388`: 2 x 512-sample rings (`+0x4`, `+0x804`) | ~18k instr |
| Delay | `0xb8482c` (call `0x1c1c58`) | `0xa08`-`0xa12` -> `0x257934` | DDR `0x8005912c`: 2 x 524,288-sample rings (`+0x4`, `+0x200004`), 4 MiB | ~6k instr |
| Reverb | `0xb836bc` (call `0x1c1d11`) | `0xa1a`-`0xa24` -> `0x257918` | DDR `0x80000018`, `0x59114` bytes: pre-delay 16,384, 8 x 1,024, 8 x 8,192 samples | ~18k instr |
| Master compressor | `0xb8541d` (call `0x1c215c`) | `0xa40`-`0xa4e`, `0xd4`/`0xd6` -> `0x257964` | L1 `0x257ab0` (376 bytes) | ~19k instr |

- **The frame on the DSP side.** The render function `0x1c2712` reads the ColdFire's TX frame as an
  image at DM `0x25c48c`. Every offset from T3.3 lines up: the global FX block `0x9fa`-`0xa52` is read
  at `0x25ce86`-`0x25cede`, the compressor routing `0xd4`/`0xd6` at `0x25c560`, and the per-voice
  DEL/REV/CHR sends of slot 0 (`+0x7a/+0x7c/+0x7e`) are the start pointers of the `0x92`-stride
  voice loop (`0x25c5e0/e2/e4`). The image is filled by 672-word copies (`0xa80` bytes, the TX
  payload length) from the render's third argument: one at the end of each pass (`0x1c302d`), and
  one at the start that runs only when a flag is set (`0x1c287a`). **[verified]**
- **Unpacking.** `0x1c2dfc`-`0x1c302a` converts the global block to floats, mostly `float(v) * F15`.
  `F15 = 0x38010204` = 1/32512 is set at `0x1c2b23`. 32512 = `0x7f00` is T3.3's `127 << 8`, so a
  0..127 knob becomes 0..1. The voice loop's side blocks also write `R15`, so that `F15` still holds
  this value here is **[inferred]**, though the match with `0x7f00` makes it likely. A few words
  (WID, FDBK, pans) use `float R by R14` instead, probably `* 2^-15`. The floats go into five
  structs: reverb `0x257918`, delay `0x257934`, chorus `0x257950`, compressor `0x257964`, and
  mixer/master fields `0x2579cc`-`0x257aac`. **[verified]** for which word goes where (table in
  section 1).
- **Order of processing.** Audio Task `0x1c9fe7` -> block handler `0x1c9d6b` -> command 3 `0x1c9f0f`
  -> render `0x1c2712` (call `0x1c9fbc`) -> voices `0x1c8ef1` (call `0x1c3044`) -> **FX bus `0x1c1738`**
  (call `0x1c3054`: send sums, then chorus, delay, reverb) -> **master `0x1c1f1e`** (call `0x1c305d`:
  compressor routing, compressor, master overdrive, pattern volume). Each of these has exactly one
  static caller, and the three FX calls and the compressor call are unconditional, so all four
  effects run on every block whatever their settings. **[verified]**
- **Cross-sends in the code match the UI.** After the chorus call, `chorus->delay` (`k29`, `0x257a6c`)
  and `chorus->reverb` (`k30`, `0x257a70`) add the chorus output into the delay and reverb inputs.
  `delay->reverb` (`k38`, `0x257a20`) adds the delay output into the reverb input. **[verified]**
- **Compressor fingerprint.** The ratio table at `0x2cfde0` holds 1/1.5, 1/2, 1/3, 1/4, 1/6, 1/8,
  1/16 and 1/20. That is 8 ratios, and the last is 20, which matches T3.3's "index 7 shows 20.00".
  The threshold maps to -60..0 dB (`60*THR - 60`), and level detection and gain are computed in dB
  with `log` and `powf` once per sample. **[verified]** for the table and constants.
- **No hardware circular buffers.** None of the four routine trees touches an L or B register for
  addressing. Every ring wraps in software: an AND with `len-1`, or `fext` of 9 bits (chorus) or 19
  bits (delay). **[verified]** Replacement code can follow the same C-runtime convention, with the
  L registers left at 0. **[inferred]**
- **Cost** (static instruction count x loop trips, 32-sample block, no stalls): about 18k (chorus),
  6k (delay), 18k (reverb) and 19k (compressor) instructions per block, about 61k in total. At 48 kHz
  / 32 samples there are 1,500 blocks per second, so that is about 92M instructions per second, about
  9% of a 1 GHz ADSP-21569, before DDR stalls. The unit's real DSP clock is not known. The chorus
  and compressor are expensive for what they do: the chorus makes a function call per sample, per
  biquad and per one-pole filter, and the compressor calls `powf` and `log` per sample. **[inferred]**
  (method in section 5).

## 1. Where the frame lands, and who reads each FX word

**Frame image at DM `0x25c48c`.** [verified]
- `0x1c2712` loads `I5 = 0x25c48c` at `0x1c2877` and `I4 = 0x25c48c` at `0x1c301a`. The image has
  40 other references, all absolute loads inside `0x1c2712` (`0x1c2888`-`0x1c3005`). Its only
  stores are two 672-word copy loops (672 x 4 = `0xa80` bytes, the TX payload length):
  `0x1c287a`, at the start of the render (skipped by `JUMP IF SV` at `0x1c2872`, so it is
  conditional), and `0x1c302d`, the last step of the render (unconditional). Both copy from
  `DM(I6-32)`, the render's third argument (`R12`, saved at `0x1c2767`), which the command-3 case
  passes as `I3` (`0x1c9fb5`).
- So, apart from the pass where the first copy runs, the global FX reads see the frame copied at the
  end of the previous block, one block (0.67 ms) late. **[inferred]** from the order of the copies. Where `I3` points (the SPI
  receive buffer; `0x1ca46a` sets up the link with `0x2c0240`) is not traced here. **[open]**
- The offsets are byte offsets, and 16-bit frame words land at the same offsets as on the ColdFire,
  as digikit found on the Digitakt II. A 32-bit load at an even offset `o` returns word `o` in its
  low half and word `o+2` in its high half (`fext-se(R, 0, 16)` / `ashift(R, -16)`).

## 2. The FX bus and the master stage

Call chain (every edge is the function's only static caller) **[verified]**:

```
Audio Task 0x1c9fe7 -> block handler 0x1c9d6b -> jump table 0x268a68[3] = 0x1c9f0f (command 3)
  -> 0x1c2712 render (call 0x1c9fbc)
       0x1c2dfc-0x1c302a  unpack global FX block (section 1)
       -> 0x1c8ef1 voices / per-slot stages (call 0x1c3044)
       -> 0x1c1738 FX bus (call 0x1c3054)
            0x1c177b-0x1c18b8  16 rows x 32 samples: row outputs 0x257ee8 + 0x100*r (32 L + 32 R floats)
                               x per-row send gains -> three send buses
            -> 0xb84d5c chorus (call 0x1c1be1)
            chorus out x k29 -> delay bus;   chorus out x k30 -> reverb bus
            -> 0xb8482c delay  (call 0x1c1c58)
            delay out x k38 -> reverb bus
            -> 0xb836bc reverb (call 0x1c1d11)
            returns x VOL (k31 0x257a64, k39 0x257a18, k47 0x2579cc), external input (0x1c1e1f path)
       -> 0x1c1f1e master (call 0x1c305d)
            16-track sums split by the routing mask 0x257984; IN/FX bits 0x257988 add inputs/returns
            -> 0xb8541d compressor (call 0x1c215c), 0x25b968/0x25b9e8 -> 0x25ba68/0x25bae8
            -> master overdrive: gain from k68 into 0x257c28/0x257c88, then per channel
               0x1c6664 (state 0x257ce8/0x257d20, into 0x25d0b8/0x25d1b8),
               0x1cdc30 (state 0x257c28/0x257c88), 0xb82728 (state 0x257d58/0x257dd0, 32 samples)
            -> pattern volume k69 (0x257a78) squared, ramped in 1/32 steps, 32 samples (0x1c22ad)
```

- Every effect is called the same way: `R4` = state, `R8` = parameter struct, `R12` = an I/O
  descriptor at `0x257e6c`. That descriptor holds `+0` the block length (32, `0x1c14a8`), `+4` the
  input pointer pair and `+0xc` the output pointer pair. The FX bus writes `1.0` into a last field of
  each parameter struct just before the call: reverb `+0x18` (`0x257930`), delay `+0x18`
  (`0x25794c`), chorus `+0x10` (`0x257960`). **[verified]**
- Init: main `0x1ca76b` calls `0x1c1445` (call `0x1ca804`). That stores 48000.0 (`0x473b8000`) and 32
  in a config block at `0x257e5c`, then calls each effect's init with the same state and parameter
  pointers: reverb `0xb83dc1`, delay `0xb848cb`, chorus `0xb84f51`, compressor `0xb85501`. It also
  sets up the master stages `0x1cdac1` (x2), `0x1c6726` (x2) and `0xb8282e` (x2). **[verified]** So
  the effects run at **48 kHz in 32-sample blocks**, 1,500 blocks per second. **[verified]** for the
  constants; **[inferred]** that this is the run-time rate.
- **DDR placement.** The three time-based effects keep their state in DDR, back to back:
  reverb `0x80000018` (size `0x59114`, which its init passes as `R12` at `0xb83dc1`), delay
  `0x8005912c` (the next byte), chorus `0x80459388`. The compressor state is in L1 at `0x257ab0`.
  **[verified]** These are in the zero-filled DDR range the boot stream loads (T3.1:
  `0x80000000`-`0x8052fbe0`).

## 3. The four effects

All four are tied to their parameters by dataflow (sections 1 and 2) **[verified]**. The role named
for each sub-routine is **[inferred]** from its structure unless marked.

### 3.1 Chorus: `0xb84d5c`

Arguments: state `R4 = 0x80459388` (DDR), parameters `R8 = 0x257950` (`+0` DPTH, `+4` SPD, `+8` HPF,
`+0xc` WDTH, `+0x10` = 1.0). Init: `0xb84f51`, whose `0xb84f20` clears the rings with a 256-pass
loop.

| step | routine | what it does | evidence |
|---|---|---|---|
| 1 | `0xb84c1f` | parameter update, once per block | reads params `+0`, `+4`, `+8`, `+0xc`, `+0x10` [verified]. `HPF*127` is clamped and truncated into an index into a 128-entry coefficient table at `0x2cfbc0` (first word 0.99478). `SPD*2.82 + 0.28` looks like an LFO rate. A coefficient is raised to the 256th power (8 squarings at `0xb84c99`-`0xb84ca3`). Writes state `+0x1188`.. |
| 2 | `0xb80c39` x2 | input high-pass: a one-pole filter `0xb809f2` called **once per sample** | `y = a*x + b*x1 - c*y1` on state `+0x1130` (L) and `+0x11a0` (R); output to work buffers `+0x1004` (L) and `+0x1084` (R) [verified for the arithmetic] |
| 3 | `0xb84b39` | **modulated delay**: a hand-made per-sample loop (`R14` = block length, back branch `0xb84bf5`) | rings L at state `+0x4` and R at `+0x804`, **512 samples each** (indexes wrapped with `fext(...,0,9)` at `0xb84ba1`-`0xb84bb8`). Each sample: `0xb84a3b` computes the modulation, two taps per channel are read and **linearly interpolated** (`(a-b)*frac + b`, `0xb84bd0`-`0xb84be0`), the input is written at the write index (`+0x1104`), and the index is incremented mod 512 [verified for the instructions] |
| 4 | `0xb84ccb` | 6 biquads, 3 per channel, in series | `0x1cdfa1` calls the direct-form-I biquad `0x1cdf46` (5 coefficients, 4 state words) **once per sample**. States at `+0x1210/+0x1234/+0x1258` (L) and `+0x127c/+0x12a0/+0x12c4` (R). `0x1cdf73` resets a biquad and `0x1cdf85` sets it to pass-through [verified for the arithmetic] |
| 5 | `0xb8499c` | output, 2 channels x 32, gain ramp into the output buffers | literal 2-pass loop around a 31-pass loop, per-sample output index from `M4 = DM(I5)` [verified for the loops] |

- The table at `0x2cfb40` has 32 rising values, 259.3 to 368.4. These look like delay times in
  samples (5.4 to 7.7 ms at 48 kHz), indexed from DPTH/WDTH. **[inferred]**
- State size is about `0x1310` bytes (highest offset seen `+0x12c4` plus one biquad). The DDR
  region from `0x80459388` up to `0x8052fbe0` (T3.1's loaded DDR end) is about 858 KB, much more than
  the chorus needs. What else lives there is not known. **[open]**
- **Why it is called a chorus**, besides the parameter routing: short rings (512 samples, 10.7 ms),
  read positions modulated every sample, interpolated reads, no feedback write-back from the output

  for those instructions.

### 3.4 Master compressor: `0xb8541d`

Arguments: state `R4 = 0x257ab0` (L1, up to `0x257c28`: 376 bytes), parameters `R8 = 0x257964`
(`+0` SCF, `+4` THR, `+8` ratio, `+0xc` ATK, `+0x10` REL, `+0x14` MUP, `+0x18` MIX, `+0x1c` SCS,

`0xb8541d` sets up pointers and calls `0xb85396`, which runs five stages **[verified for the calls]**:

| step | routine | what it does | evidence |
|---|---|---|---|
| 1 | `0xb84fd3` | **side-chain filter**, once per channel (back branch `0xb85054`, `R14 = 2`) | loads table `0x2d0400` (128 rising values from 0.0013) and calls `0xb80bfc` (coefficients, inferred); `0xb80c6e` runs a 32-pass loop with an inner 3-section loop plus a one-pole per sample (`0xb809f2`) |
| 2 | `0xb85070` | **level detector**, per sample (back branch `0xb850f4`, `R15` = block length) | `max(|L|,|R|)` (`0xb850c7`-`0xb850cf`), floor `powf(2,-23)`, then `log` (`0x1c0b60`, constants log10(e), ln 2) times 20 (`R13 = 20.0`). ## 4. Rough cost per audio block (for the CPU-monitor work)

Static estimate, in instructions per 32-sample block (`scripts/t34_cost.py`; full trees in
`out/T3.4/cost_*.txt`). Method and limits are in section 5. Treat the figures as ±50% and probably
high, because both arms of every branch are counted.

| effect | total | main parts |
|---|---:|---|
| Chorus `0xb84d5c` | ~17,900 | per-sample modulated read `0xb84b39` ~9,100 (a modulation call per sample); 6 biquads `0xb84ccb` ~6,150 (one call per sample per biquad); input one-poles 2 x ~850; output ~720 |
| Delay `0xb8482c` | ~6,300 | ring write and feedback `0xb83f72` ~2,100; output ~1,150; feedback-path soft clip and filters `0xb84099` ~1,080; positions ~700; parameters ~700 |
| Reverb `0xb836bc` | ~18,200 | tank `0xb82d1a` ~10,100 (of which 8 one-pole damping calls ~2,700); 8-line diffuser bank `0xb82a5b` ~5,500; input ~1,100; output ~730 |
| Compressor `0xb8541d` | ~18,700 | level detector `0xb85070` ~7,400 (`powf` + `log` per sample); gain computer `0xb851e5` ~6,100 (`powf` per sample); side-chain filter ~3,900; output ~790; smoothing ~310 |
| **four effects** | **~61,000** | |
| FX bus `0x1c1738` without the effects | ~11,700 | 16 rows x 32 samples x 3 sends, cross-sends, returns |
| master `0x1c1f1e` without the compressor | ~13,600 | routing sums ~7,900; overdrive chain ~5,700 (`0x1c6664`, `0x1cdc30`, `0xb82728`, two each) |

- **Budget.** 48 kHz in 32-sample blocks is 1,500 blocks per second, so one block lasts 0.667 ms.
  An ADSP-21569 at its 1 GHz maximum has 666,667 cycles per block. The four effects would be about
  61k, roughly 9%, at one instruction per cycle with no stalls. The unit's real core clock is not
  known (it could be lower), and the DDR-resident rings will add stall cycles that this count does
  not see. A measured figure needs T4.1 (the `EMUCLK` read at the block handler `0x1c9d6b`).
  **[inferred]**
- **Where a rewrite would win** (for G1-G3, G9): the compressor computes `powf`/`log` twice per
  sample (`powf(2,-23)` is a constant computed 32 times per block). The chorus and reverb call
  one-sample filter functions in loops (`0xb809f2`, `0x1cdf46`, `0xb82a17`), paying call overhead
  (about 6-8 instructions) per sample per filter. Per-block coefficient work is small everywhere.
  **[inferred]**
- For context, the same counter gives about 258k instructions for the whole render `0x1c2712`
  (with the 16-voice dispatch `0x1c8ef1` at about 150k). That figure is weaker, because `0x1c8ef1`
  dispatches through indirect jumps that the walker does not follow. **[inferred]**

## 5. Method and limits

- **Static base.** digikit's sharcdb (`insn`, `edges`, `literals`, `mem_access`, `ptr`) and its
  `tools/sharc.py` API (`last_def` for loop counts). Listings: `scripts/t34_lst.py`. Image words:
  `scripts/t34_rd.py` (run from `vendor/digikit` with `uv run`).
- **Walker** (`scripts/t34_tree.py`). From an entry, it follows fall-through, jumps and conditional
  jumps (delay slots included) up to the returns, and recurses into calls. It lists DO loops,
  absolute addresses and literals. Function boundaries in the database are sometimes wrong (two
  effect entries, `0xb8482c` and `0xb836bc`, sit inside other "functions"), so the walker starts from
  the call target, not from the database's function.
- **Cost** (`scripts/t34_cost.py`). Each reachable instruction counts once, times the product of
  its enclosing loop trip counts. Calls add the callee's cost plus 6 instructions. Literal DO counts
  are used as they are. Register DO counts are 32 (each one checked with `last_def`: the block
  length, or `dec` of it, from the stack argument). The three SIMD loops in the reverb tank are 16
  (`lshift(R15,-1)`). Five loops built from a backward conditional jump are entered by hand
  (`BACK`). `powf` `0x1c0c76` is fixed at 150, its 127-instruction main path plus a reciprocal,
  because the walk includes its error paths. Not modelled: branch probabilities, pipeline and memory
  stalls, cache, DMA. The reverb's tap loops include both arms of a zero-fill branch.
- **Decoder cross-check** (`scripts/t34_xcheck.py` -> `out/T3.4/xcheck.txt`). Across the cited
  ranges (unpack, FX-bus calls, master calls, chorus loop and output, delay write, reverb diffuser
  and damping loops, reverb init, compressor detector and gain computer, biquad), selache's listings
  start an instruction at 1,147 of digikit's 1,217 starts. 1,133 of those have identical bytes. The
  14 that differ, and the 70 starts selache does not share, are its known width bugs on 48-bit
  multifunction forms (T3.1), each followed by a few instructions of resync. Every load-bearing
  instruction quoted here (the frame loads, the 672-word copy `lcntr=0x2a0`, the four effect
  calls, `fext ... 0x0:0x9`, `i3=0x2cfde0`, `r15=0x38010204`, `r9=0x3e124925`) decodes the same
  in both. One exception: selache prints `???` for the short-word load at `0x1c2dfc`. **[verified]**

## 6. How sure: found, candidates, unknown

**Found with confidence** (dataflow from the frame word to a struct, struct to a single call, plus
matching structure):
- Chorus `0xb84d5c`, delay `0xb8482c`, reverb `0xb836bc`, master compressor `0xb8541d`; their call
  sites, parameter structs, state addresses, DDR sizes and audio buffers.
- The frame image `0x25c48c` and the reader of every global FX word (section 1). The compressor's
  ratio table, which matches the UI.
- Delay ring 2 x 2^19 samples, chorus rings 2 x 512, reverb line sizes (16,384, 8 x 1,024,
  8 x 8,192). No hardware circular buffering anywhere in the four effects.

**Candidates** (structure fits, role not proven):
- The roles of the sub-routines inside each effect (section 3 tables): in the chorus, LFO
  `0xb84a3b` and the 6-biquad tone filter `0xb84ccb`; in the delay, the soft clip
  `x*(2-|x|)` in the feedback path (`0xb84099`) and the tempo-synced time code; in the reverb,
  pre-delay, diffuser bank and tank; in the compressor, which table is attack and which is release.
- The master overdrive chain after the compressor (`0x1c6664` -> `0x1cdc30` -> `0xb82728`, per
  channel), which looks like oversampling around a saturator. Not part of this task.
- The header flag bits that zero the cross-sends (per-effect mute or kill bits).

**Unknown**:
- Where the per-voice send gains (`k86`-`k88`) end up after the voice loop, and the stride-`0x1c`
  row table the FX bus reads.
- Where the SPI receive buffer is (the render's third argument).
- The reverb topology in detail (FDN or allpass loop), and the exact parameter curves (the
  coefficient tables are known by address, not by meaning).
- `k40` Delay FX Routing is never read. `k48` Reverb FX Routing is stored as a flag
  (`0x2579d4`), but no reader of that byte was found by absolute address. These are consistent with
  T3.3's guess that both are left over. **[verified]** negative for `k40` (no load covers
  `0x25cea4`); `k48`'s reader search covered absolute addresses only.
- The DSP core clock, and real cycle counts (stalls, DDR latency).

## 7. Next steps (sound simulation, splicing, CPU monitor)

1. **Simulator stage 2 (T3.6) has a clean first target.** Each effect is one call with a fixed
   convention: `R4` = state, `R8` = parameter struct (floats 0..1), `R12` = the descriptor at
   `0x257e6c` (`{32, &in[2], -, &out[2]}`), and buffers of 32 floats. The delay is the smallest
   (~6k instructions per block; no `powf` or `log`). Running `0xb8482c` on an impulse with a
   zeroed 4 MiB state needs only DM and DDR memory, and no peripherals. Then the chorus, then the
   reverb. The compressor needs `powf`/`log` (`0x1c0c76`, `0x1c0b60`) to execute correctly.
2. **Reference recordings (T3.5)** can now be specified per parameter: each knob's struct field and
   scaling are known (section 1), so a recording with fixed knob values maps to exact float inputs.
3. **Splice (T3.8).** The four effects are reached by one direct call each (`0x1c1be1`, `0x1c1c58`,
   `0x1c1d11`, `0x1c215c`). Redirecting one call to new code with the same signature replaces an
   effect without touching the bus. The first patch, a gain change on the chorus, can wrap
   `0xb84d5c` and scale its output buffers `0x25b668`/`0x25b6e8`.
4. **CPU monitor (T4.1):** read `EMUCLK` around the four call sites to get real per-effect cycles,
   and compare them with section 4.
5. **Upstream (when results exist):** digikit's function table merges the delay and reverb entries
   into their neighbours (`0xb8482c` inside `0xb8478d`, `0xb836bc` inside `0xb836ac`), and the
   effects cluster `0xb836ac`-`0xb85530` has no names. This note can become a digikit findings page.
