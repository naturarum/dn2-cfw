# T5.0b: FTN1, the flanger and the tape delay named on the screen

Date: 2026-10-12 (background agent). Firmware: Digitone II OS 1.12, main OS loaded at `0x40000400`.
Marks: **[verified]** = checked against the bytes or run in the emulator here; **[inferred]** = reasoned
from structure. Emulator and tools only: nothing flashed, nothing committed, nothing pushed.

## Summary

FTN1 = FTD1's DSP (our flanger in the chorus slot, our tape delay in the delay slot; section 7 byte for
byte) + core-dn2 0.1 (the hook bus, the same build as DC01/DH01) + a new elekloader mod, **fx-rename-dn2
0.1**, which only repoints names. No new rows, knobs, glyphs or code: 29 sites, each one pointer or one
`pea` operand, and 195 bytes of strings. The knob labels of both pages stay (DPTH SPD HPF WDTH; TIME X
WID FDBK HPF LPF).

- **Build** [verified]: `out/T5.0b/FTN1.syx`, 2,418,208 bytes, sha256
  `60d1cd1fc35a0505fdeb451c727b570047e85c416a43930e673d611bbf4a58e8`, version field FTN1. Its main OS
  (`out/T5.0b/FTN1.main.bin`, sha256 `0bce4860...0c35e`) differs from stock in 41 ranges: core's 12 (as
  in DC01/DH01), the 29 names, and the 1,000-byte blob appended at `0x4030c980`. Sections 2, 4, 5, 8
  are stock byte for byte, section 7 is FTD1's byte for byte (stored and depacked).
- **Cold boot** [verified]: FTN1 boots from reset to the same main screen as stock, pixel for pixel. The
  titles built at boot read **Tape (1/3)** and **Flanger (3/3)**, which closes T5.0's open item (the
  renamed title had never been seen).
- **Screens** [verified]: 28 screens, stock and FTN1, same keys from the same state. 7 are identical;
  in the other 21 the only pixels that differ are the renamed words (table in section 3.2). LEDs
  identical on all 28.
- **Same parameters** [verified]: after the tour (14 knob turns, an LFO destination picked from the list, two parameter locks),
  the parameter mirror and the ColdFire-to-DSP frame are byte-identical between stock and FTN1, at the
  start and at the end. The renamed rows keep their CC, NRPN, k and every other field.
- **Brick checker** [verified]: **ACCEPT, 12 PASS, 0 FAIL, 0 SKIP**, with `--intended-main
  out/T5.0b/FTN1.main.bin` and `--intended-dsp out/T3.8/FTD1/section7.bin`
  (`out/brickcheck/FTN1-2026-10-12/report.md`, 48 min). In-place margins +2,151,844 at `0x40400000`
  and +54,692 at `0x40200000` (stock +2,128,334 / +31,182); 41 changed ranges, 1,164 bytes, sections 3
  and 7 differ; the emulated cold boot latched the main screen at 741,672,000 instructions with a PNG
  byte-identical to stock's (and FTD1's); one `0x9F` (JEDEC ID) flash command at boot as stock, no write,
  erase or protect; the DSP run is FTD1's (1,500 blocks, peak 0.683, 341,040 instructions/block against
  stock's 320,281).
- **Not done**: anything on the unit. The emulator has no DSP, so the sound (FTD1's) is not part of
  this test; it was tested for FTD1 in T3.8.

Rows are descriptor rows (`0x401f83a4 + 0x3c * row`): `+0x28` is the long name (the header's "Name=value",
the destination list), `+0x30` the short label under the knob. Each site's stock pointer or instruction
is read from the image and checked by `scripts/t50b_make_mod.py` before the site is written [verified].

**The renaming method** is T5.0's section 3 (`notes/T5.0-flanger-page-ui.md`), cut down to its labels:
- the descriptor table is in the image and read each time a page is drawn, so a `ptr` site that points a
  row at a string in the mod's `.run` (copied to `0x47E00000` by core's boot code) works from the first
  frame;
- the page titles and short names are `std::string`s that the static initializer `0x400c2c4e` builds at
  boot from a `pea` of a literal, so the `keep2` sites change that operand. The constructor copies the
  characters, so the page record holds its own copy;
- the box is drawn at each frame from another `pea` of the same literal.

Never edit a stock string in place: "DEL" (`0x40210dd1`) is also the AMP envelope's Delay Time (row
`0x3d`), the filter envelope's Env. Delay (row `0x2c`) and Delay FX Routing (row `0x7a`); "Delay Send"
and "Chorus Send" are the tails of "In Delay Send" and "In Chorus Send"; "Delay" is the tail of
"Env. Delay". Relabelling by repointing these pointers, and the page records, are dn2_firmware_explore's
findings on OS 1.11 (credited in `NOTICE`); the 1.12 addresses here were found and checked in this
project. None of their code or text is used.

**Data only, no code.** The mod has no `ev_` handler and no code of its own. Of the 29 sites, 23 are
pointers in data tables and 6 change only the 32-bit operand of a `pea` (the opcode word `4879` stays).
The title needed no code at boot: the core's boot copy runs from the OS entry's call at `0x40000538`,
before the static initializers, so the strings are in place when the page records are built
[verified by the cold boot, section 3].

## 2. What stays

- **Every knob keeps its parameter.** In the main OS that FTN1 depacks to, the descriptor table differs
  from stock only in the 22 name words above (`+0x28`/`+0x30` of 11 rows): type, id, range, default, MIDI
  CC (`+0x18`), NRPN (`+0x1c`), flags and formatter are stock (`out/T5.0b/build.json`, check
  "descriptor table: only +0x28/+0x30 words changed") [verified]. So MIDI CC numbers, NRPN, storage
  (the mirror index k) and the DSP frame word of each renamed knob are unchanged.
- **Census.** Every 32-bit value in the image equal to the address of "Chorus", "Delay", "CHO", "CHR",
  "LCHR", "RCHR", "DEL", "LDEL", "RDEL", or one of the long names above, was listed (descriptor
  fields, `pea` operands, other tables) [verified]. Each one is either renamed above or left stock for
  a reason below.
- **Left stock on purpose:**
  - the knob labels of both pages (the owner's choice: they fit the new effects);
  - each row's group pointer `+0x2c` ("Chorus", "Delay"): no code reads it. Static: none of the functions that
    reference the table reads `+0x2c` from it (indexed reads `(0x2c,An,Dn)`, the address `0x401f83d0`,
    and row pointers built from the base were all checked; the one-field accessors read `+0x0`, `+0x4`,
    `+0x14`, `+0x18`, `+0x1a`, `+0x1c`, `+0x24`, `+0x28`, `+0x30`, `+0x34`) [verified, disassembly]. Dynamic:
    a read watch on the whole table during the full screen tour, on stock and on FTN1, saw reads of
    `+0x0`, `+0x4`, `+0x8`, `+0xc`, `+0x10`, `+0x20`, `+0x24`, `+0x28`, `+0x30` and `+0x34`, and not one of
    `+0x2c` (section 3.4) [verified];
  - row `0x7a` "Delay FX Routing"/DEL: no page shows it (T3.3, and the page records in RAM) [verified];
  - the AMP and filter envelope rows that share "DEL" (rows `0x3d`, `0x2c`);
  - the destination lists' group `0x10` entry ("ERR"): the chorus rows carry no destination flags
    (`+0x24` = 0), so it is never shown [verified: flags; inferred: never shown];
  - a second table of names at `0x401d0f04` (184 rows of `0x3c` bytes, long/group/short at `+0/+4/+8`,
    with the old "Chorus Send"/"CHR" etc.). Nothing points into it: a scan of every 16-bit-aligned word of
    the image finds no value in `0x401d0e00-0x401d3a30` except one constant load [verified]. Left alone.
  - "CHORUS" (`0x40215a35`, a song part name) and "DELAY" (`0x40220fc8`, a word of the random name list)
    are not the effects [verified, their tables].
- **No MIDI or CC name list**: CC numbers are fixed per row (`+0x18`, unchanged) and the census found no
  other table of these names, so there is nothing else to rename for MIDI [inferred: the MIDI track
  pages were not visited].

### 3.1 Build checks

`scripts/t50b_build.py` runs everything from the sources and refuses on any failed check [verified,

## 4. Limits

- **Emulator only.** No DSP, no USB MIDI, no +Drive content beyond the factory kit. The sound is FTD1's
  and is not tested here.
- **The destination lists' group `0x12` name ("DEL" -> "TAPE") was not seen on any screen.** The delay
  rows carry destination flags (`+0x24` = `0x1e00`), but they belong to the FX parameter set, and no
  screen we found lists them; the track LFOs list the track's rows only. Renamed for consistency, at no
  risk (a pointer to a 4-character string) [inferred].
- **The page records' short names** ("TAP", "FLG") are built and held in RAM [verified], but no screen
  in the tour reads them; the SEND FX box comes from its own `pea` [verified].
- **Screens not in the tour**: the dual-mono variants are covered (16c-16e) but SOUND/kit browsers,
  the MIDI track pages and the PERFORM views were not visited; nothing there names these effects by the
  strings above, as far as the pointer census shows (section 2) [inferred].
- **The brick checker** counts as a full gate for name and repack changes only until T1.7b's gaps are
  closed (HANDOFF); FTN1's code changes are the core's, already checked for DC01/DH01.
- **Order on the unit**: FTN1 is the first build that changes both the main OS (through the core) and
  the DSP. FTD1 (DSP only) and DH01 (core only) should each work on the unit first.
