# T3.3 (effects part): FX and master parameters in the ColdFire-to-DSP frame, Digitone II 1.12

Date: 2026-10-05. Image: main OS 1.12 (`out/decomp/main_os`). Marks: **[verified]** = checked against bytes
or measured in the emulator; **[inferred]** = reasoned from code structure.

## Summary

- **All send-effect, compressor, external-input and master parameters travel in one contiguous block of
  the TX frame: offsets `0x9fa`-`0xa53`, one big-endian word per parameter,**
  `frame offset = 0x9fa + 2*(k - 25)` where `k` is the parameter's mirror index (the `+0x04` field of its
  row in the descriptor table `0x401f83a4`). Chorus is `k` 25-31, delay 32-40, reverb 41-48, external
  input 49-59, compressor 60-67, master overdrive 68, pattern volume 69. [verified: static path, and
  every parameter turned in the emulator landed at the predicted offset; see the table]
- The per-track FX page (BR, OVER, SRR, routing switches, and the three send levels) sits in the
  `0x92`-byte per-voice slots at `0xda + 0x92*r`, copied into every voice row the track owns; the owner
  track of row `r` is at `0xa5a + 2r`. [verified]
- Compressor routing (which tracks, inputs and send FX go through the compressor) is two words, `0xd4`
  (track mask) and `0xd6` (IN L, IN R, SEND FX bits). [verified, with one host-called copy]
- **Value encoding:** the value the UI stores is `value << 8` (0..`0x7f00` for a 0..127 parameter;
  delay TIME and feedback carry a fractional low byte). The frame carries a smoothed copy: each frame,
  `FUN_400db28e` moves a 32-bit state 3% of the way towards the stored value (EMAC, coefficients
  `0x03d7` and `0x7c29`, which sum to `0x8000`), and the frame word is the rounded upper half. So on the
  unit the frame word settles at the stored `value << 8`. [inferred from the EMAC code; see "Emulator
  caveat"]
- **Emulator caveat:** digikit's patched Unicorn does not implement the EMAC's fractional mode (MACSR
  `0x20`). Each product comes out half as large as the ColdFire's definition says, so in the emulator
  the smoothing settles at about `stored / 34.3` instead of `stored`. The offsets measured in the
  emulator are right; the absolute frame values there are not the unit's. [verified with a two-instruction
  test of the firmware's own `macw`/`macl` encodings, `scripts/` below]

## Method

1. Static: the frame handler, the copies into the frame, and the setter path from an FX page to the
   mirror (`out/decomp/main_os`).
2. Dynamic: `scripts/t33_session.py` drives digikit's `tools/guirun.py` from a main-screen snapshot
   (`out/T3.3/snaps/main720M.snap`, saved 320M instructions after `boot400M`). It opens a page with
   panel keys, then turns each encoder up and down, saving a snapshot and a screen PNG after each turn.
   A write watch on the whole raw mirror (`0x80003af0`, `0xd8c` bytes) logs every parameter write.
   `scripts/t33_frame.py` restores each snapshot, enters the vector-191 handler 60 times by hand (the
   emulator never raises vector 191 itself) with the DSPI2 driver stubbed, and saves the TX buffer.
   `scripts/t33_diff.py` diffs consecutive steps. `scripts/t33_run.sh` chains the three.

## Table: FX and master parameters in the TX frame

Frame = the `0xa80`-byte payload the ColdFire hands the DSPI2 driver (`FUN_400cf922(0xa80, 0x80005e60,
0xabc, 0x800053a4)`, call at `0x40025e9e`); offsets are from `0x80005e60`. All fields are big-endian
16-bit words. `k` = mirror index = descriptor `+0x04` (`scripts/dn2_param_table.py params`, saved as
`out/T3.3/param_table.txt`). Encoders: A-H = wire channels 0-7, LEVEL = channel 8.

**Encoding, every row unless noted:** stored value `v << 8` (`v` = the 0..127 or 0..N number on screen;
a bipolar knob shows `v - 64`; an enumerated one stores its index). The frame word is the smoothed copy
of it (see Summary). "dyn" = in the emulator the encoder turn wrote exactly this mirror word and changed
this frame word (in a few steps the emulated smoothing rounded a fine change away, e.g. TIME `2f00` ->
`2ee2`; another step of the same parameter then showed it), `[verified]`; "static" = from the code only,
`[inferred]`.

### Per-voice FX (track FX page, [FX]) and track level

The frame has 16 per-row slots of `0x92` bytes at `0xda + 0x92*r`. **A row is a voice, not a track:**
`FUN_4002585a` writes a track parameter into every row whose owner word `0x80005308 + 4r` equals the
track, and the frame carries that owner at `0xa5a + 2r` (low word). In the LIGHTHOUSE pattern all 16 rows
belong to track 1, so one turn changed all 16 slots; turning track 2-8 levels on MIXER 2 changed nothing,
because no voice belonged to those tracks. [verified]

## Static path, from the FX page to the frame [verified against the disassembly]

1. **UI to mirror.** `FxParameterSet::vslot13` (`0x40038f78`) and `::vslot31` (`0x40037d86`) resolve a
   descriptor row to its mirror index with `FUN_400dbe28` (`move.l (0x4,A0,D0*1),D0` on row
   `0x401f83a4 + 0x3c*row`, `0x400dbe46`), reject `k >= 0x65`, and call `FUN_4002585a(value, 0x10, k)`.
   The writes seen in the emulator took the notification branch: `FxParameterSet::vslot31` calls a
   listener through its vtable at `0x40037f24` (return `0x40037f26` on the stack), and the listener
   `FUN_4003f8ce` calls `FUN_4002585a` at `0x4003f962` (return `0x4003f968`). [verified: stack scan at
   the watch hit, `out/T3.3/probe/log.txt`]
2. **`FUN_4002585a(value, track, k)`** (`0x4002585a`): for `track == 0x10` it stores the word at
   `0x80003af2 + 2*(k + 0x660)` = `0x800047b2 + 2k`, which is raw-mirror row 16. For a real track it
   stores into every row `r` whose owner `0x80005308 + 4r` equals the track, at `0x80003b12 + 0xca*r + 2k`.
3. **Whole-block copy.** `FUN_40025444(fx)` (`0x40025444`) copies the FX setup's 101 words (`0xca` bytes)
   to `0x800047b2`, records `fx` in `0x800052a4`, and copies the long at `fx + 0xca` to `0x80005214`. The
   frame handler calls it at `0x40026b2a` when `*(0x800052a0) + 0x48e4 != *(0x800052a4)`, but only inside
   its sequencer-event loop. `FUN_40025b6e` clears `0x800052a4` to request it; the routing page does that
   (watch: 8 clears, no mirror write).
4. **Smoothing.** The handler calls `FUN_400db28e(0x80003af0)` (`0x4002717e`): 1,734 words (17 header
   words + 17 rows of `0xca` bytes, so row 16 included) go through a one-pole filter into `0x800068e4`,
   with 32-bit state at `0x8000de60`. It then copies the `0x990`-byte machine table raw
   (`0x8000487c` -> `0x80007670`) and passes the LFO destination words (row offsets `0x2a`, `0x3a`,
   `0x4a`) through unfiltered.
5. **Into the frame** (handler `FUN_40025e36`, `0x400274fa`-`0x40027680`): per row `r` (`A5` steps `0xca`
   from `0x800068e4`, `A4` steps `0x92` from `0x80005e60`) four `FUN_40134770` copies: `0x52` bytes from
   row `+0x54` to slot `+0xda`, `0x1c` from `+0xa6` to `+0x12c`, `0x1a` from `+0xc2` to `+0x148`, `0xa` from
   `+0xe0` to `+0x162`. Row offset `0x22 + 2k` is index `k` (the first `0x22` bytes are the 16-word header),
   so the copies carry `k` 25-92 and 95-99, and a row's top indices lie in the next row's header area
   because the row stride (`0xca`) is the parameter count, not the span. Then the global block: five copies
   from the smoothed row 16, `0xe` bytes from `0x800068e4 + 0xcf4` to `0x8000685a` (frame `0x9fa`), `0x12`
   from `+0xd02` to `0xa08`, `0x10` from `+0xd14` to `0xa1a`, `0x16` from `+0xd24` to `0xa2a`, `0x10` from
   `+0xd3a` to `0xa40`, and one long from `+0xd4a` to `0xa50`. Since `0x800068e4 + 0xcc2 + 2k` is index `k`
   of row 16, these are `k` 25-31, 32-40, 41-48, 49-59, 60-67 and 68-69: chorus, delay, reverb, external
   input, compressor, master. The group boundaries match the descriptor groups `0x10`, `0x12`, `0x11`,
   `0x15`, `0x14`, `0x13` exactly.
6. **Send.** At the next vector 191 the handler first sends the buffer it built last time
   (`0x40025e8a`-`0x40025e9e`), then rebuilds it, so a change reaches the DSP one frame later, and the
   smoothing spreads it over many frames.

## Emulator findings (useful beyond this task)

- **EMAC fractional mode is wrong in digikit's Unicorn.** `scripts/t33_emac_test.py` runs the
  firmware's own `macw %d6u,%d0u,%a1@,%d4,%acc0` (`a891 00c6`) and `macl %d5,%d4,%acc0` (`a805 0800`) with
  MACSR `0x20` (F/I = 1, as the handler sets it at `0x40025e7c`): `0x03d7 * 0x7f00` gives `0x01e7a900`
  (the fractional result is `0x03cf5200`), and `0x7c290000 * 0x10000000` gives `0x07c29000` (fractional:
  `0x0f852000`). Output: `out/T3.3/emac_test.txt`. [verified] Every one of 11,115 global-block frame
  words captured here equals the filter's steady state under that wrong arithmetic, about `stored/34.3`
  (`scripts/t33_emac_model.py`, `out/T3.3/emac_model_check.txt`). [verified] The LFO and modulation code
  (`msacw` in the modulation kernel) and anything else that runs the EMAC in fractional mode will be off
  the same way in the emulator. Worth reporting to digikit.
- **Encoders: the first events of a turn are swallowed.** A lone encoder event, or the first one or two
  events on an encoder after a pause, never changes the value; later events in the same turn do, and
  `+32` raw units moved a 0..127 parameter by 10. So `t33_session.py` sends a wake event and then the real
  one, and `--pairs 2` repeats the up/down pair; with that every parameter changed. Why (acceleration,
  touch detection) is not traced. [verified: behaviour; cause open]
- **guirun's button pacing.** With the default `--panel-dwell 16`, button events were delivered about
  9M instructions apart, so in the first session FUNC was still held during the first encoder turns.
  `--panel-dwell 0` with events 2M apart works for FUNC+key chords. [verified]
- **Frame capture works on 1.12 with the sequencer stopped:** `t33_frame.py` enters the vector-191
  handler and it returns every time (60 to 400 passes per snapshot). With the sequencer playing (PLAY
  pressed), the second pass does not return within 5M instructions (stuck at `0x4011edee`), the same
  wall digikit hit on the Digitakt II. Frames from those runs (`out/T3.3/frames/routing-play-*`) are not
  used. [verified]
- **FX-setup recopy is lazy.** The compressor routing page only clears `0x800052a4`; the handler recopies
  the FX setup inside its sequencer-event loop, which the stopped-sequencer capture never reaches. The
  routing rows above were measured by calling `FUN_40025444` once from the host before the passes
  (`t33_frame.py --fx-copy`), which is a calibration, not natural execution. The page edits
  themselves (FX setup `+0xca`: `0x0000ffff` -> `0x0004ffff`, `0x0003ffff`, `0x0000fffe`) were read from
  the snapshots without any host call (`scripts/t33_fxsetup.py`, `out/T3.3/diffs/routing-fxsetup.txt`).

## Open

- **Delay FX Routing (`k` 40) and Reverb FX Routing (`k` 48):** in the frame (`0xa18`, `0xa28`) and in
  the descriptor table, but no page I opened writes them, and the compressor routing page uses the
  `+0xca` bits instead. They may be left over from an older OS. [inferred]
- **The unit's frame values** are inferred from the EMAC definition; the emulator cannot show them
  until its fractional mode is fixed. A cheap check on the unit is not possible without a DSP-side probe.
- **What the SHARC does with each word** (scaling, curves, where chorus, delay and reverb read them) is
  T3.4's job. The DSP side should read the global block at receive offsets `0x9fa`-`0xa53` and the
  routing at `0xd4`/`0xd6`, which gives T3.4 a search key: in digikit's DT2 work the frame reader indexes
  the receive buffer with immediates such as `0x94` and `0x73c`, so look for `0x9fa`-`0xa52` immediates.
- Not covered: the per-track AMP and FLTR pages (only the FX page and track level were turned), the
  INTERNAL MIXER page 2 (tracks 9-16, same mechanism as page 1), and the encoder push buttons.
